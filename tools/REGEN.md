# Regenerating the generated Unicode tables

Two headers are generated from CPython's own Unicode data — do not edit either by hand:

- `include/real/unicode/unicode_fold.hpp` — case-fold orbits, by `tools/gen_unicode_fold.py` (see below).
- `include/real/unicode/unicode_props.hpp` — the `\w` / `\d` / `\s` property ranges, by
  `tools/gen_unicode_props.py`.

## The `\w` / `\d` / `\s` property table (unicode_props.hpp)

```sh
python3 tools/gen_unicode_props.py           # writes include/real/unicode/unicode_props.hpp (~2 s)
# update the pinned version in tests/test_unicode_props.cpp if it changed, then re-run the gate
make full-local-gate
```

Source of truth is CPython's `re`: the generator asks `re.fullmatch(r'\w'/'\d'/'\s', chr(cp))` for
every code point (surrogates excluded), coalesces the matches into ranges, then **re-checks every
code point against `re` and aborts on any mismatch**, and asserts the exact totals (Unicode 16.0.0:
`\w` 142940 cp / 771 ranges, `\d` 760 / 71, `\s` 29 / 10). `test_unicode_props_regen.py` regenerates
in a temp file and asserts byte-identity (skipped when the running Python's Unicode version differs
from the pin). **A regen that changes any range is a BREAKING change for the Unicode-shorthand
behaviour** — call it out in the release notes, do not bump silently.

## The case-fold orbit table (unicode_fold.hpp)

`include/real/unicode/unicode_fold.hpp` is generated by `tools/gen_unicode_fold.py`. Do not edit it by hand.

## Binary-property source data (`tools/ucd/`)

`tools/ucd/DerivedCoreProperties.txt`, `tools/ucd/PropList.txt` and `tools/ucd/emoji-data.txt`
are committed, unmodified UCD 16.0.0 source files (same version as `tools/ucd/Scripts.txt`),
fetched from:

- `https://www.unicode.org/Public/16.0.0/ucd/DerivedCoreProperties.txt`
- `https://www.unicode.org/Public/16.0.0/ucd/PropList.txt`
- `https://www.unicode.org/Public/16.0.0/ucd/emoji/emoji-data.txt`

They are the direct source for the `\p{...}` Unicode *binary properties* (`\p{Alphabetic}`,
`\p{White_Space}`, `\p{Emoji}`, …) — parsed like `Scripts.txt` (a committed raw UCD file, not
derived from `unicodedata`), by `tools/gen_unicode_binprop_tables.py`, into
`include/real/unicode/unicode_binprop.hpp`. Do not hand-edit any of the three; re-fetch the same
URLs at the pinned version to update, and re-run the generator.

## Script_Extensions source data (`tools/ucd/`)

`tools/ucd/ScriptExtensions.txt` and `tools/ucd/PropertyValueAliases.txt` are committed, unmodified
UCD 16.0.0 source files, fetched from:

- `https://www.unicode.org/Public/16.0.0/ucd/ScriptExtensions.txt`
- `https://www.unicode.org/Public/16.0.0/ucd/PropertyValueAliases.txt`

Together they are the source for `\p{scx=...}`. `ScriptExtensions.txt` lists, in the short 4-letter
UAX24 script codes (`Latn`, `Grek`, …), the code points whose Script_Extensions set is an explicit
override of more than one script (e.g. U+0660 ARABIC-INDIC DIGIT ZERO: `Script=Arabic` but
`scx={Arab, Thaa, Yezi, ...}`); every other code point's scx defaults to its single `Script` value.
`PropertyValueAliases.txt` is needed only to map those short codes to the long names REAL's `script`
enum already uses (`Scripts.txt` itself never uses the short form) — `tools/gen_unicode_scx_tables.py`
reuses `gen_unicode_script_tables.py`'s own `script` enum and aliases rather than redefining them.
Emits `include/real/unicode/unicode_scx.hpp`. Do not hand-edit either file; re-fetch the same URLs at
the pinned version to update, and re-run the generator.

## When to regenerate

- After a CPython upgrade that bumps the bundled Unicode data version (`unicodedata.unidata_version`).
  The header pins the version it was built from (`unicode_fold_unidata_version`), asserted by
  `tests/test_unicode_fold.cpp` and by `bindings/python/tests/test_unicode_fold_regen.py`.

**A regenerated table that changes any orbit is a BREAKING change for text-mode `icase` users** — the
set of characters a cased literal or class matches would shift (e.g. a new case pair added in a later
Unicode version). Treat a regen with orbit changes as a minor/breaking release, not a silent bump:
call it out in the release notes.

## How

```sh
python3 tools/gen_unicode_fold.py            # writes include/real/unicode/unicode_fold.hpp
# then update the pinned version in tests/test_unicode_fold.cpp if it changed, and re-run the gate
make full-local-gate
```

## Source of truth and determinism

The orbits are built from, and **exhaustively validated against, CPython's own case-insensitive
matching** (`re.IGNORECASE`) — not from `CaseFolding.txt` directly. This is deliberate: REAL's
text-mode `flags::icase` oracle *is* `re.IGNORECASE`, so deriving the table from the same relation
makes them identical by construction rather than by hopeful agreement. The generator:

1. builds fold orbits with a union-find over `str.lower/upper/casefold` + `re._compiler._EXTRA_CASES`;
2. repairs code points with multi-character case mappings (e.g. U+0130 İ, which `re` single-folds to
   `i`) using `re` as the oracle;
3. **aborts** unless every cased code point's `re.IGNORECASE` match set equals its computed orbit.

For a fixed CPython Unicode version the output is byte-identical, so `test_unicode_fold_regen.py`
regenerates in a temp file and asserts it matches the committed header (skipped when the running
Python's Unicode version differs from the pin).
