# v2026.7.39 — the C ABI foundation (R4: Go/JS-ready)

Bindings-frontier release: the C ABI grows from 14 to 20 functions, and Python's
`RegexSet` is rewired onto the native fused multi-pattern engine. Zero engine
changes — every addition is additive-strict (no existing signature or value
changed; `rust-test`'s 100% pass against the unmodified Rust crate is the proof).

## C ABI — 14 → 20 functions

Three new entry points close the gaps a Go, Node, or Ruby binding would otherwise
have had to work around:

- **`real_match(re, text, len, start, end, mode, spans)`** — search, match, and
  fullmatch as ONE function (`REAL_MODE_SEARCH`/`REAL_MODE_MATCH`/
  `REAL_MODE_FULLMATCH`), mirroring `real::regex`'s own region-aware C++
  overloads. Previously there was no way to expose `fullmatch` through the ABI
  at all.
- **`real_find_iter_between(re, text, len, start, end)`** — iteration bounded on
  both sides (Python `finditer`'s `pos`/`endpos`), a separate function rather than
  an overload of `real_find_iter_at` — this ABI has no default arguments.
- **`real_sub(re, text, len, repl, repl_len, count, out, outlen, n_subs, errbuf,
  errbuf_len)`** — Python `re`-compatible replacement templates (`\N`,
  `\g<n>`/`\g<name>`, octal, escape letters), the two-call size-then-fill
  convention `real_group_name` already established. The algorithm is ported from
  the Python binding's own proven `parse_template` (`real::detail::
  decode_digit_escape` is the shared, already-tested primitive both use) minus
  the Python C-API coupling — an octal escape is always exactly one raw byte
  here (the ABI is byte-oriented), unlike the Python binding's str-mode UTF-8
  re-encoding of a high value.

**Acceptance criterion for this train**: a Go or JS binding can now implement
compile/search/match/fullmatch/finditer/sub/groups/set without touching C++.
`findall`/`split` stay intentionally client-side over `finditer` + spans — a
documented, not missing, design choice.

The header itself now states, once, for the whole surface: the thread-safety
contract (a `const` handle is safe to share and match against concurrently, no
locking needed — previously stated only informally in the Python binding's own
comments), the native-vs-`re` flag-numbering table (every flag's bit value
differs between REAL's native bitmask and Python's `re` module — the documented
first mistake a binding author porting from Python would make), and the
error-sentinel convention (NULL / -1 / `(size_t)-1`, no error state held between
calls) in one place instead of scattered per-function.

`fuzz_capi.cpp` now drives the entire surface — `real_count_matches`, all three
`real_match` modes, `real_find_iter_between`, `real_sub`, every `real_set_*` —
the same raw-pointer boundary that caught the wagon-4c OOB. ~110k runs clean
under ASan/UBSan/libFuzzer, 0 crashes. `test_capi.c`'s smoke coverage extended
in parallel, oracle spans hand-verified.

## `RegexSet` (Python) — native, not a Python loop

`real.RegexSet` previously looped N individual `Pattern.search()` calls in
Python. It now wraps `real::regex_set` directly (`bindings/python/src/
_real.cpp`, not through the C ABI — that ABI is byte-oriented and would force
an unneeded str/bytes round trip) — the same Stage-1 N-walks / Stage-2 fused
single-pass DFA the C++ engine has had since `regex_set.hpp` shipped, now
actually reachable from Python. The public constructor shape
(`RegexSet(patterns, flags=0)`, directly instantiable) is unchanged — a thin
Python wrapper around a new internal `_RegexSet` type plus a `_compile_set`
factory, matching `Pattern`/`Match`'s own `DISALLOW_INSTANTIATION` + factory
convention.

**Numbers, both hands measured independently**: small sets (below the fused
threshold, `regex_set.hpp`'s `fused_min_eligible = 56`) are ~28% faster — pure
Python-call-overhead removal, N searches now loop inside C++ instead of N
Python method calls. Fused-eligible sets are **~5-9× faster, shape-dependent**
— one measurement landed 8.8× (a 70-pattern / ~1 MiB-text corpus, matching a
direct C++-level probe of the identical corpus almost exactly), an independent
second measurement on a different pattern shape landed 4.7×; both real, the
gap is the shape, not a discrepancy. A pattern that is not DFA-eligible
(lookaround, Unicode `\w`/`\d`/`\s`, …) silently falls back to per-pattern
N-walks within the set — exactly the existing C++ behavior, unchanged.

## Honesty: the bug the benchmark caught, not the tests

`RegexSetObject`'s region-parsing helper resolved an *unset* `endpos` to the
subject's concrete byte length before calling into `regex_set::matches`/
`is_match` — which check `pos == 0 && endpos == real::npos` **exactly** to
decide whether the fused Stage-2 pass is eligible at all. Every call was
silently forced onto the slower N-walks path, region requested or not. The two
new differential tests (parity against the old N-loop's own logic, kept as the
oracle) never caught this — a wrong-but-consistent route still produces the
same list of booleans, and *was* still correct. It surfaced only because the
before/after benchmark for a 70-pattern fused-eligible set came back
suspiciously flat (~1%) instead of the multiple-times win the underlying C++
engine measurably delivers on its own. A performance assertion caught what a
correctness assertion structurally cannot: two different routes to the same
right answer are indistinguishable by result alone. Fixed by only resolving
`endpos` to a concrete offset when the caller actually passed one, leaving it
at `real::npos` otherwise — re-measured post-fix (the ~5-9× above).

## Verification

Full C++ test suite (590 tests, 52.7k checks) unaffected — R4 touches no
`include/real/` engine code, bindings only. `make full-local-gate` 18/18.
`rust-test`: 100% across the entire crate, unmodified — the additive-strict
proof. `python-test`: 151/151, including the two new RegexSet differential
tests (Stage-1 and the 70-pattern Stage-2 fused case, `uses_fused() == 1`
independently confirmed via a direct probe). `fuzz_capi.cpp`: ~110k runs,
0 crashes, full new surface covered. Two doc micro-fixes from an independent
header review folded in before this stamp: `real_compile`'s flag list was
missing `dollar_endonly`; the multi-pattern section header still said
"Stage-1 N-walks", stale since the fused path is the real route once eligible
— both corrected.
