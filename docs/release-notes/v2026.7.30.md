# v2026.7.30 — multi-pattern fused + prefilter throughput arc

Stage-2 fused which-matched, Arc I first-byte skip on the fused scan, and Arc II B1
word-boundary wraps on shape fast-paths land together. Multi-pattern and prefilter
throughput move measurably; the engine stays linear and ReDoS-safe. No native JIT
(header-only / constexpr / portable moat preserved).

## Multi-pattern: fused which-matched (Stage-2)

`regex_set` / `RegexSet` (which-matched) no longer always walks N independent
searches. When enough patterns are DFA-eligible (≥ 56, calibrated crossover), a
**fused single-pass** automaton records which rules hit at least once:

- **Flat ~400 MB/s** in N on large eligible sets (vs pure N-walks collapsing to
  tens of MB/s at N=128–256) — typically **4–10×** our own N-walks at large N.
- **vs RE2::Set same-host:** quasi-parity on dense log-like corpora (~0.9–0.97×);
  **~1.2× ahead of RE2::Set on sparse-realistic text** after Arc I first-byte skip
  (measured, dual-regime tables in `docs/BENCHMARKS.md`).
- **Lookbehind / lookarounds in the set** still compile (ineligible members stay on
  N-walks); RE2::Set cannot compile them — capability differentiator, not a speed claim.
- Small sets and region searches keep pure N-walks. Hybrid remaps fused rule indices
  to construction order (interleaved lookarounds tested).

`real::dfa` munch (lexer one-winner) is unchanged and is **not** this API.

## Arc I — set-level first-byte skip on fused scan

When the fused walk is at the start state, bytes that cannot begin any rule are
skipped (union of per-rule `first_bytes`; disabled if any rule lacks a sound
first-byte set). Pure opt: with-skip == without-skip == N×search.

Honest dual stamp (arm64 M1, same harness as RE2::Set):

| Regime | vs no-skip | vs RE2::Set |
| --- | --- | --- |
| Sparse-realistic | ~+40% | **~1.2× ahead** |
| Dense log-like | ~+10–12% | ~0.95–0.97× (not a rout) |

## Arc II B1 — `\b` / `\B` on shape fast-paths

Patterns that already had SIMD / exact-literal / fixed-alternation paths but lost
them under word-boundary asserts re-use those paths: scan as before, then **O(1)
boundary check** at the match start/end.

Fair same-hit-count vs unwrapped proxy (arm64):

| Pattern | Before (dense) | After |
| --- | --- | --- |
| `\b[0-9a-f]{8}\b` | ~0.1× proxy (~57 MB/s) | **~1.0× SIMD proxy** (~540 MB/s) |
| `(?:foo\|bar)\b` | ~0.14× | ~0.84–0.96× proxy |
| `\bERROR\b` | exact-literal + replay | stays on that path with trail `\b` |

**Not** a general assertion-DFA. `$` and complex assert shapes outside fixed-shape /
alternation / exact-literal remain deferred (Arc II closed on B1 after a post-B1
re-measure: remaining fair gaps are smaller / dense-only or confounded hit-counts).

## Bindings

- **Rust:** `count_matches` via the C ABI (closes the C++/Python gap from 7.28–7.29).
- Python / C set APIs unchanged in surface; they inherit fused routing from C++.

## Internal / quality

- Prefilter O(n) smoke no longer uses wall-clock ratios (flaked twice on shared CI).
  Test binary bills a **deterministic work counter** (`REAL_TEST_INSTRUMENT`); production
  wheels leave billing a no-op. Margin 25× unchanged (O(n)≈8×, O(n²)≈64×).

## Honesty — competitive position

- **Ahead of** `std::regex` (always) and **RE2 monopattern** (always, measured 1.4–8×).
- **Multi-pattern which-matched:** competitive-to-ahead of RE2::Set on the measured
  regimes above; lookaround-in-set capability RE2::Set lacks.
- **PCRE2-JIT:** still mixed / ISA-dependent on daily class scans; PCRE2 still leads
  fixed `date` / bare `literal` on both ISAs (JIT specialization). We do **not** chase
  that with a native JIT.
- **Hyperscan:** different job (thousands of literals / streaming). On moderate-N
  which-matched our fused path is in the same ballpark as RE2::Set; we do not claim
  “faster than Hyperscan.”

Reproduce multi-pattern numbers with `benchmarks/s2a_measure.cpp` (optional RE2) and

and same-host ratios are the durable content.
