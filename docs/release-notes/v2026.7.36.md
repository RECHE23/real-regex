# v2026.7.36 — possessive quantifiers, now fast

Performance release. Closes most of the possessive-vs-greedy gap v2026.7.35
disclosed: the dominant possessive/atomic shapes now run through dedicated
fast-path routes instead of the general VM. No breaking API changes, no
semantic changes — every existing pattern matches exactly as before.

## Performance — the gap closed, on the dominant shapes

v2026.7.35 shipped possessive quantifiers and atomic groups correct but
slow: up to ~4-6× (arm64) / ~18× (x86-64) slower than the greedy
equivalent, because the possessive path ran entirely through the general
VM. This release adds two new recognizers and two new runners
(unbounded possessive class/code-point-point loops, bare/suffixed or
literal-delimited) dispatched ahead of the general VM, additively —
**zero lines of any existing runner were touched** (proof by diff, not
by promise).

The result: `"[^"]*+"`, the dominant "quoted string" shape, now runs
**faster than its own greedy equivalent** — 0.44× (arm64) / 0.46×
(x86-64) — because a possessive loop never gives back, so the new
runner needs none of the backtracking-adjacent machinery a greedy scan
carries. Bare, suffixed, and `\b`-wrapped class loops (`[a-z]++`,
`\d++x`, `\b[a-z]++\b`, `\w++`) now run at or near class-loop speed,
down from the original ~9-18× gap.

Two shapes are deliberately left on the general VM, and say so in the
routing rather than silently degrading: a possessive loop whose class
overlaps a literal delimiter's own bytes (`id=[a-z0-9]*+;` — the
alphanumeric prefix is itself a member of `[a-z0-9]`, which would make
a skip-based retry unsound, not just slower to reason about), and a
possessive quantifier over a single literal byte rather than a class
(`a*+`, `(a)*+` — greedy has no dedicated whole-pattern byte-loop fast
path either, so this isn't a regression relative to greedy, just an
unclaimed opportunity).

One disclosed residual: an unrelated fast path (`.` over a single
emoji code point) shows a reproducible ~5% cost on arm64 in the
standard non-regression set, most likely an instruction-cache/layout
shift from this file's net growth — proof-by-diff confirms not one
byte of that runner changed. The same case is a net *gain* on x86-64,
consistent with a layout-shift cause rather than a logic change. One
mitigation attempt (moving a profiling call out of the hot dispatch
path) did not resolve it on arm64; every other case in the standard
set stays within measurement noise on both ISAs.

## Correctness

A route-toggle differential (forcing every new fast path off and
comparing against the identical route-auto result) is the primary
proof, not the benchmark numbers: 12,720 checks across a randomized
sweep of body/quantifier/prefix/suffix combinations, full/prefix-mode
edge cases, and adversarial inputs (no closing delimiter, delimiter-
free text), on both ISAs — zero divergences. The differential fuzzer's
pattern generator was extended with a dedicated "quoted"/delimited
possessive shape generator so the offline fuzz run exercises these
routes against `re` directly, independent of the route-toggle check.

One bug was caught and fixed before this ever shipped: a captured
possessive class loop (`([a-z])*+b`) has no `save` instruction
preceding its loop opcode by Tier 1's own design (a speculative save
would corrupt a prior iteration's capture) — the capture slot is only
visible on the loop opcode's own field. An earlier version of the new
recognizer assumed a preceding save and silently never armed for any
captured class loop; caught by the permanent test's own initially
wrong hand-derived expectation, before commit.

## Honesty

This is a real, substantial, disclosed win, not a full close of the
gap: the two declined shapes stay exactly as slow as they were, on
purpose, because doing them safely needs more than what "additive,
narrow, measured" scope allows in one train (see `\ref div_possessive`
in the C++ docs). The dot-emoji residual is reported as found —
reproducible on one ISA, absent (reversed, even) on the other — rather
than smoothed over because the headline numbers were already good
enough to ship without it.
