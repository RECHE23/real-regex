# v2026.7.59 — the one-pass table stops being expensive to build

A **performance** release on the per-regex build path, plus one compile-time fix the
fuzzer found. No API changes, no behaviour changes: every span, every capture group
and every match count is byte-identical to v2026.7.58, verified as a differential
against the same engine with the routes switched off rather than asserted — 494
pattern × subject pairs on spans, 28 on every capture group of every match.

## The row this was about

`(\w+)@(\w+)` on first use has been disclosed and not chased in three consecutive
releases. It moves here:

| criterion row | v2026.7.58 | v2026.7.59 | vs the `regex` crate |
| --- | ---: | ---: | :--- |
| `first_use/email` | 2.78 ms | **1.58 ms** | 4.57× behind → **2.66× behind** |

Direct harness, construct plus one search, arm64: `(\w+)@(\w+)` 2729.3 → **1538.2 µs
(−43.6 %)**, `(\d+)@(\d+)` 189.7 → **105.0 (−44.6 %)**. x86-64 instruction counts for
the same build fall **39.7 %**, and allocations from 601 486 blocks to 236 566.

## Four steps, every one picked by a profile

The method is worth stating because it decided the outcome twice. Profiling per
function contradicted the obvious guess on the first step, and contradicted a
measurement instrument on the last.

**Byte equivalence by signature, not pairwise comparison.** The build's largest cost
was not the minimizer at 19.1 % but `compute_lazy_alphabet` at 26.5 %. A byte's
signature — which predicates hold it — does not depend on the classes formed so far,
so it can be built once and grouped. Comparing each byte against every open class
re-walked all the predicates per (byte, class) pair: O(256 × classes × predicates),
9.2 M instructions a call against this pattern's 475 predicates.

**Minimization rows split by what varies.** Only `cls[i]` and the `cls[edge.next]`
change between rounds; class indices and capture/assert masks are fixed for the whole
call. Those invariants are grouped once into an `inv_id`, so a round's signature is
41 words instead of 162. The round loop also reads a packed run of assigned targets
rather than walking all 103 of a node's edges to find the 39.4 that matter.

**The trie's sequences move into one buffer.** They were a vector OF vectors, each 1
to 4 ranges growing from empty, re-allocating at 1, 2 and 4 — 164 220 blocks holding
755 KB, an average block of 4.6 bytes. And its recursion allocated again per interval
per level; it now hands its child a prefix of its own compacted buffer.

**The alphabet transpose reads the bitmap instead of testing it.** A `\w` predicate
holds 63 of 256 bytes, and the class *is* a bitmap, so iterating its set bits is 63
scatters against 256 tested branches — across 475 predicates.

## The compile-time fix, and what found it

CI's fuzzer timed out at 10 seconds on `\w{500}accc…` with icase, inside
`unicode_casefold`. Pre-existing, and measured as such rather than assumed: the exact
reproducer, rebuilt from the log, took 12.10 s on the commit before the one that
surfaced it and 12.00 s on that commit.

What it exposes is real — the linear-time guarantee covers **matching**; nothing
covered compile. The fold loop scanned all 2940 table entries per class, asking
`any_of` over the class's ranges for each (`\w` carries 771), and a repeat folds the
same class once per repetition. The table is sorted by code point, so each range now
seeks its first entry and walks forward while still inside.

| compiling `\w{k}a` with icase, arm64 | before | after |
| --- | ---: | ---: |
| k = 50 | 25.50 ms | **3.32** |
| k = 200 | 76.94 | **13.29** |
| k = 800 | 305.14 | **51.02** |

The fuzz reproducer, same flags as CI: **12.22 s → 1.86 s**.

This is the second train running where the fuzzer found a cost defect the benchmark
suite structurally cannot: the benchmarks measure patterns people write, the fuzzer
measures patterns that are merely legal.

## What it costs

Nothing measurable. Every criterion row other than `first_use/email` lands within
±1.7 %, the walk is unchanged on the direct harness (`\w+` and `[a-z]+` 0.0 %, `\d+`
−0.1 %), and patterns whose build is already cheap do not move (`\w+`, `\d+`,
`[a-z]+` at 0.0 % on first use).

Two rows first read as regressions and were resolved rather than published: over two
rounds `find/digits` showed +12.5 % and `find/word_bound` +4.2 %; over four rounds of
5 s they are **+0.8 %** and **+0.3 %**, with per-round dispersion at 0.2 %.

## One hypothesis refuted, and why it is here

callgrind put a `memset` in `minimize` at **4.87 %** of the build — the 4096-entry
bucket-head refill per round. Replacing it with a round stamp, and dropping a
`next_cls` clear that was provably dead work, moved arm64 wall clock **−0.2 %** and
x86-64 instructions **−0.2 %**. `rep stos` is a known over-count in callgrind and
this is what that looks like. The change was reverted: no complexity without a
measured gain, and it is named in the commit so it is not retried.

## Verification

Output identity was re-verified after each step, not assumed: `compute_lazy_alphabet`
returns byte-identical alphabets on 20 patterns (count and all 256 assignments); the
minimized one-pass automaton is identical on 28 (eligibility, node/class/slot counts,
and a digest over every edge's assigned/next/cap_mask/assert_mask); the casefolded
classes are identical on 60 pattern × case combinations, including `İıſK`, `ǅǆǄ`,
`µΩÅ`, fullwidth, ligatures, astral and negated forms.

Criterion figures come from an interleaved A/B against v2026.7.58 with the same bench
file on both sides, one group at a time, machine otherwise idle. `full-local-gate` on
every commit in the train, plus CI green including the windows-msvc leg and the fuzz
job that first failed. 777 tests, 345 104 checks. Coverage 95.62 % (floor 95.0).
clang-tidy clean, MISRA 0, sanitizers clean, Go and Python bindings green, gcc-14
green, unicode-fold regeneration guard green.

## Notes

Nothing here changes what REAL matches. The linear-time / ReDoS-safe guarantee and
the bounded lookarounds are unchanged, and so is the API.
