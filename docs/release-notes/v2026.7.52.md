# v2026.7.52 — perf train: fast-path dead-store trims + the inner-literal cold-safe floor

A **performance** release, and the first engine-hot-path train since the
fidelity work. Every change here is measured on the ProxMox devbox and, per
the repository's law, confirmed on **both ISAs** (x86_64 and arm64) with
interleaved same-host A/B; the Rust-crate duel figures below are same-host
x86_64. Two dead-store removals on the fast-path success exits, a re-derived
inner-literal size floor that flips the `\w+@\w+` throughput back ahead of the
Rust `regex` crate at common corpus sizes, and a regression net that closes a
matrix coverage hole.

## Performance (3 engine changes)

1. **A′ — drop the dead `npos` slot-fill on fast-path success** (`f0ef689`).
   The dedicated fast paths (`run_class_loop`, `run_cp_class_loop`, the
   fixed-shape and alternation routes) opened each match by assigning `npos`
   to every capture slot, then immediately overwrote the real spans via
   `fill_span_slots`. On the *success* exit that pre-fill is pure dead
   store — the spans are always written before anyone reads them. Replaced
   with `ensure_size` (grow-only, never-shrink), so the slots are sized but
   not zeroed. Measured **−3% to −6% across the `class+` family**, 2-ISA,
   zero regression on the flat witnesses. The failure path keeps the `npos`
   assign untouched (consumers read slots on `!matched`).

2. **L1 — the same trim on the exact-literal success exit** (`dd16f4d`).
   `replay_literal` pre-assigned `npos` to all slots, then replayed the saves.
   The pre-assign was dead except that the group-0-end fallback keyed off
   `out_slots[1] == npos` to detect "save 1 absent"; that fallback is now
   **unconditional** (`out_slots[1] = cand + len` always — it is always the
   group-0 end, and save 1 would rewrite it identically), so the pre-assign
   drops. Coverage proven structurally: every slot on the exact-literal path
   is written by the replayed saves. Measured **−7.1% on the literal route**
   (x86 instruction count; arm64 carried the flat-witness non-regression).

3. **P1 — re-derive the inner-literal size floor, ×64 → ×28** (`88179b5`).
   The inner-literal route gates on a per-regex `il_min_haystack` floor
   (`prefix_program_size × N`, clamped `[64 KB, 512 KB]`). Re-measurement
   showed the warm dense crossover for the email `\w+` prefix has **collapsed**
   — the routed path beats the core from ~4 KB (2-ISA) — so the old `×64`
   (→ ~220 KB for that prefix) had become a dead warm ceiling: it forced the
   slower core below 220 KB and **lost ~1.4× to the Rust `regex` crate** on
   `(\w+)@(\w+)` at common sizes. The floor is now set **cold-safe rather than
   at the warm crossover**: `×28` → the email floor lands at ~94 KB. The
   96–192 KB window flips from a ~1.4× loss to a ~1.35× **win** vs Rust, and
   the flip is confirmed at 96 KB on both ISAs. Honest cost, stated in the
   header comment: the 94–128 KB *cold-dense one-shot* window pays ~1–2.4%
   versus the core (the cold-dense curve never crosses on either ISA) — the
   accepted price for the warm win. Date-shaped prefixes (`\d{4}`) stay
   floor-clamped at 64 KB, unchanged.

## Nets

- **The 4-D veto matrix now samples the class-scan routes** (`c8bb7e0`).
  The inner-literal regression matrix previously exercised email/date/hexid
  shapes only; it now carries at least one shape per **class-scan route** —
  `class_loop` (`([a-z]+)`, `([0-9]+)`) and `cp_class_loop` (`(\w+)`), in
  mirror-group form — each gated fast-path-on vs forced-general. This closes
  the coverage hole that had once let a class-loop regression through; a
  per-route regression now reddens the gate mechanically. A `codepoint-class`
  shape and the short-run variants that the reverted O2 pass exposed remain
  on the follow-up list.

- **Measure-first, on both ISAs, held the line.** Several candidate
  optimizations were explored on the devbox and **reverted before landing**
  when the measurement — not the intuition — declined them: a dedicated URL
  fast-path (a per-iteration tax on the general case), and a codepoint-class
  ASCII-scan rewrite (an arm64 win that carried a short-run *regression* on
  x86, caught only by the mandatory second-ISA leg). What ships here is what
  survived both a correctness differential (spans bit-identical, routed ==
  core) and a 2-ISA, no-per-ISA-regression bar.
