One-pass anchored matching, and an enforced tier layout.

**Anchored one-pass matching (Tier B).** Position assertions — `^ $ \b \B \A \Z` — now compile to edge
conditions on the one-pass table, so anchored patterns that carry them extract their captures in a single
pass instead of falling back to the VM. Through the std-compat layer, `real::compat::regex_match` with
submatches runs 4.3–4.7× faster on one-pass patterns (email/date/`^\w+$`/`\b\w+\b`-style), and REAL's own
`match` / `fullmatch` inherit it. Routed matching stays byte-identical to the pure Pike VM (a population-B
differential and a rejection test prove it); the exhaustive std::regex compatibility check is unchanged.

**The engine, partitioned into enforced dependency tiers.** The headers under `include/real/` now sit in
tiers — `core` < `unicode` < the `engine`/`automata` runtime < `frontend` < the public root — and
`tools/check_layers.py` (the `check-layers` gate) fails the build on any upward include. The public include
paths — `<real/real.hpp>` and the opt-in `<real/dfa.hpp>` — do not move, so consumers see nothing change.
The tests mirror the same tiers, the reference docs move under `docs/` behind a one-page hub, and PyPI gets
its own dedicated page.

**Also.** The UTF-8 trie's memo drops `std::unordered_map` / `std::hash` for an in-house hash (a libc++
`__hash_memory` symbol drifts across toolchains); a 32-bit CI compile and a header-hygiene rule guard the
class. No semantic changes to matching — moves, additive routing, and documentation.
