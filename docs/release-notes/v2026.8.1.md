# v2026.8.1 — two routing decisions that were never measured, and a tool that finds the rest

A same-day follow-on to 8.0. Two performance changes, both in places the engine was deciding
something by assumption rather than by measurement, and one new instrument that found a hole in
tests written hours earlier.

Matching is unchanged. Every span, capture group and match count is identical to v2026.8.0.

## The Aho-Corasick automaton, below twelve branches

8.0 replaced a branch-count gate with a candidate-density one, and kept the old threshold as a
**domain floor** with the reason stated plainly: nothing had been measured below twelve branches,
because the threshold itself prevented taking the route there. The gate removed that obstacle, so
the measurement became possible — and the floor was holding back a large win.

Lowered to four (below that, still nothing is measured). Default path against the cascade that
shipped:

| branches | cand/1000B | arm64 | x86-64 |
| ---: | ---: | ---: | ---: |
| 4 | 600 | 3.48× | 4.34× |
| 6 | 600 | 4.36× | 6.29× |
| 8 | 600 | 5.28× | 8.90× |
| 11 | 600 | 8.03× | **10.23×** |
| 11 | 200 | 1.74× | 2.24× |
| 4…11 | 50…100 | 0.99–1.01× | 0.98–1.02× |

**The safe direction reverses below twelve, so the constant does too.** At or above the threshold the
automaton was taken *unconditionally*, so switching early could not be worse than what it replaced —
the constant there is the measured **minimum**. Below it the automaton was taken *never*, so
switching early **is** a regression against what ships, and the constant is the measured **maximum**.
Same product rule, opposite tail. A `static_assert` now holds the relationship between the two,
because swapping them leaves both regions unsound while every test still passes.

**The sample window is sized by the verdict** rather than fixed. Deciding on ~8 candidates takes
`8000 × branches / threshold` bytes, which is ~350 for 24 branches and ~23 for 4 — the low region
demands a far higher density and reaches certainty in a fraction of the bytes. A fixed 256 made every
sparse short alternation pay a full-window scan it could not need, measured at 2–5 % on subjects that
stay on the cascade. With the window sized, those rows read 0.98–1.02× on both platforms.

## `regex_set` built a DFA per pattern to discover it did not need one

Construction partitions members into DFA-eligible and ineligible by building a full single-pattern
munch DFA for each and discarding it. When the eligible count then falls short of the fusion
threshold, both lists are cleared and every member goes back to N-walks — so for any set under the
threshold, all of that work was thrown away without ever affecting an outcome.

A set smaller than the threshold can never reach it, because the eligible subset is at most the whole
set. The partition is skipped outright:

| | before | after | |
| --- | ---: | ---: | ---: |
| 20 patterns | 214.4 µs | 16.9 | **12.7×** |
| 40 patterns | 446.9 µs | 34.0 | **13.1×** |

That is 11.2 µs per pattern of pure waste, on every set under 56 — the common size.

**Stopped there, and the measurement is why.** The probe still runs for sets past the threshold, and
replacing it with a cheaper eligibility check is worth 9–17 %: the fused subset construction
dominates and grows superlinearly. Doing it correctly needs an exact fallback for a pattern that
passes the cheap check and then explodes in subset construction. Real complexity, for a minority of a
cost that is not the probe's.

## A sabotage sweep, and the hole it found in tests written the same day

Line coverage says a line *ran*, not that anything depended on its value. `make sabotage-sweep`
perturbs each of the engine's decision constants by 4× in both directions and requires that some test
notice.

The first row that mattered was ours. The AC density threshold came back **unguarded**, hours after
it shipped with three tests written specifically for it — because those tests pinned the *sign* of
the routing decision and not its value: their subjects sat at products of 6 and 3996 against a
threshold of 550, so it could move to 137 or 2200 and every one still passed. Bracketing tests now
sit either side of it, and of the inner-literal gate's threshold, which had the same gap for the same
reason.

The sweep's own first cut was wrong in the way it exists to catch, and its header records that rather
than hiding it: it grepped `make test | tail -5` for ctest's summary line, which `make` pushes out of
the last five lines with its own error output whenever a run fails — so every genuine catch read as a
miss and the table came back uniformly "unguarded". Calibrating against a constant already proven
guarded by hand is what exposed it.

It also **cried wolf on a whole family**, which is now built into the tool. `max_nodes`,
`state_budget` and others are only *defaults* for parameters callers override — the tests exercise
the node cap by constructing with `node_cap=2`, because a 65000-node pattern is impractical to build
organically. The boundary behaviour is tested; the default is headroom no test can hold, and an
injectable limit is better design than a hard-coded one. Those rows are labelled `INJECTABLE` now,
and the header names the three honest reasons a row comes back unguarded — only one of which is work.

## The route probe was reporting its own blind spots

8.0 shipped `route-probe` reporting **6 of 20 routes unreached**, described as "each either dead or
gated more narrowly than its author believed". That was wrong, and wrong in the direction that
flatters the tool. All six were the probe's own blind spots: three needed a subject past the
512-byte lazy-DFA floor against a corpus that topped out at 41 bytes; two needed a whole-pattern `.`
or negated class, which free composition emits about once in 2300 draws; one needed a delimited
possessive whose loop is `*+` rather than `++`, which is what the recognizer requires.

**0 of 20 now, and no dead route was ever found.** The 8.0 release notes carry a dated erratum. The
lesson sits in the probe's header, because it is the failure mode the tool invites: a tool that
cannot reach a route must never be read as evidence that the engine cannot either.

## Guarantees pinned as relations rather than values

Four `static_assert`s now hold invariants that were held by prose. The one that matters most is the
routing asymmetry above. `row_ready_bit_capacity` is another: it is the *width* of the atomic word
beside it, and the code shifts `1ULL << i` for every index under it — raise it without widening the
type and the shift is undefined behaviour while the overflow array is indexed from the wrong base,
two silent faults with no diagnostic and a green suite.

The distinction is the point, and it is the sweep's output that makes it actionable: a **measured
threshold** is answered by a test that brackets it; a **relation between constants** is answered by
an assertion, which covers every build where a test can only sample.

## Disclosed, not chased

- **The compat `regex_iterator` runs 1.8–5.5× slower than `find_iter`** on the same walk, because
  each advance is a fresh `search()` with a fresh VM state, losing every per-haystack decision. Not
  fixed: `basic_match_iterator` is 8232 bytes against that iterator's 320, and `std::regex_iterator`
  requires independent copies, so embedding the walker would clone 8 KB on every `it++`. Costed in
  place, with the shape that would work. Against the `std::regex` it replaces, the same cases run
  9.9×, 88.7× and 10.8× faster — the gap is against REAL's own best path, not the promise.
- **The arm64 crossover product is two levels, not one** — ~1050 for 12–18 branches and ~795 for
  20–24, each to within 1 % across four rounds. Reproducible and unexplained.
- **Four constants are labelled rather than tested**, because manufacturing a test for a hash width
  or for headroom against a shape the compiler does not emit would be worse than the gap.

## Verification

800 tests, 345 000+ checks, 0 failures. Line coverage 96.88 % against the 95.0 floor. All 23
`full-local-gate` steps green, CI green across its jobs. Every performance figure was measured on
both platforms — arm64 under clang and x86-64 under g++ 13.3.0 — as the minimum
across alternating rounds, against an untouched gauge read before any delta was believed.
