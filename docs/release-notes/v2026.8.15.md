# v2026.8.15 — the costs a 4 KiB benchmark cannot see

**Every number that mattered in this train is a per-CALL cost, and not one of them was visible to the
instrument that decides whether a change lands.** `docs/BENCHMARKS.md` measures throughput over 4 KiB
and 200 KB corpora, where a fixed cost per call amortises to about 0.3 % — under every noise floor this
project owns. So a regression of 6.8 % shipped, sat through a full green gate, moved none of the 26
layout rows, and was caught by a hand-written probe. The engine work below is that cost removed three
times over; the tooling work is the part that makes the next one findable without a probe.

**§A and §B were re-measured on both ISAs and neither moves.** That claim is made the hard way — paired
interleaved runs of the *same* harness built from `v2026.8.14` and from this tree, so host state cancels
instead of being argued about — and it is checked against controls that cannot have changed.

## `count_matches` stops paying for three things nobody asked for

**Captures nobody can read are no longer written.** `count_matches` returns a number, so no caller can
observe a group. Its walk now runs matching-only: the capture-free walk that `(?:...)`-only patterns
already got, where a thread's whole capture state is group 0's start in one scalar and the refcounted
copy-on-write pool is never touched. On `\b(\w+)@(\w+)\.(com|org)\b` over a 4096-byte subject the row
goes **23.89 → 17.59 ns/B**, landing *on* its non-capturing twin (16.0) — which is the claim: the
capturing pattern now costs what the same language costs without groups. 1906 increfs and 2714
copy-on-writes become zero, with the VM stepping the **same 2684 positions**. That last number is the
point: the walk is identical, only its bookkeeping is gone.

**A 440-byte view is copied once per call, not twice.** The first shape of the change mutated a local
`program_view` and handed it over — and the range copies what it is handed. On x86-64/gcc that second
copy cost a **fixed +12 to +13 ns per call**: +6.8 % on a 3-byte subject, +6.3 % at 8, +5.9 % at 24,
flat in absolute terms because it is a copy and not work. Six of six paired draws agreed and the ranges
did not overlap. The range now takes the *intent* and sets the bit on the member it was going to copy
into anyway.

**And the walk stops building an end sentinel it never reads.** `basic_match_range::end()` returns a
default-constructed iterator — the same type, carrying the same 7952-byte `state_type` — so every
range-for builds two: the one that walks, and one that exists to be compared against. No comparison
ever reads its state. The private counting walk asks `exhausted()` instead:

| leg | per call, 35-byte no-match subject | control (`search`, unchanged code) |
| --- | ---: | --- |
| arm64 / Apple clang | **217 → 97 ns** (−55 %) | 71 → 70 |
| x86-64 / gcc 15.3, idle bare metal | **210 → 110** (−48 %) | 39 → 40 |
| x86-64 / gcc 13.3, bare metal | **338 → 218** (−36 %) | 55 → 55 |
| x86-64 / gcc 13.3, in a container | **280 → 159** (−43 %) | 56 → 55 |

**No single number is published for the size, and the reason is measured.** The gap between `count` and
a hand-written sentinel-free walk reads 37 ns under gcc 15.2, 97 under gcc 15.3, 123 under Apple clang
and 131 under gcc 13.3 — a spread of 3.5×, with the two gcc 15 readings differing by 2.6× *between
themselves*. Host and microarchitecture move it as much as the compiler version does. A one-number
claim would be wrong somewhere by a factor of three.

A fifth reading was **discarded rather than averaged in**: on a loaded host the same probe read −22 %,
and the control caught it by reporting 75–83 ns where it otherwise reads 41.

## Two vehicles were refused by measurement, and `find_iter` still pays

`find_iter` is unchanged and still builds the sentinel. That is stated rather than quietly left: making
the state lazy so the sentinel becomes cheap was tried **twice** — `std::optional`, then a
`construct_at` union — and both charged the *working* iterator about 26 %, indistinguishably, on a walk
that builds no sentinel at all. It is laziness itself that is closed, not a choice of vehicle. The
remaining vehicle is a distinct sentinel type, which this API cannot take: the C binding stores an
iterator and its end in one `real_iter`, and every `std::` algorithm wanting a homogeneous pair would
stop compiling. So the saving is taken where it costs no API — a private walk with no iterator type to
preserve — and the public surface keeps its cost, named here rather than left to be rediscovered.

## The general VM stopped touching the pool on capture-free patterns

A thread's capture state, on a program with no user groups, is group 0's start and nothing else. The
epsilon walk now carries that as one scalar instead of a refcounted block: on the whitespace-trim shape
**4833 refcount and copy-on-write operations per reported match become zero**. The guard is derived
structurally rather than assumed — `save 0` must be the program's first instruction, since the walk
keeps one start for a whole closure and a branch that skipped it would inherit its sibling's — and it
required a second condition the code scan cannot see: a Tier-1 possessive with a `\b` wrap writes its
group from the fast path with no `save` opcode at all.

## A first-byte filter for small pattern sets, armed on one ISA

`regex_set` below the fused threshold now screens members by a single-block first-byte scan. It arms
**only under NEON**, and that is a measurement rather than a portability shrug: on x86-64 the 128-bit
filter loses 5.3× to glibc's `memchr`, which is ifunc-dispatched to AVX2 even in an SSE2 binary. The
repository had already decided exactly this case once, for `simd_literal_scan`, and this follows it.

## A check that had never run anywhere rejected a correct tree

The Unicode cross-oracles compare this repository's parsed tables against the third-party `regex`
module. They need it importable in the interpreter that imports the built extension — which CI never
installs and no machine had. Made runnable for the first time, they **aborted on a clean checkout**: 10
code points for `\p{Math}`, 44 for `\p{scx=...}`.

Nothing was wrong with the tables. The module ships its own property data at a later Unicode than the
UCD sources committed here, so the two sides were answering about different characters. A domain filter
— skip code points this UCD leaves unassigned — was tried and is **not enough**: it takes the
disagreements from 10 to 1 and 44 to 6, and the remainder are *assigned* code points whose property
value moved between versions (U+0306, U+0308, U+0320, U+0331 are combining marks whose
Script_Extensions set grows as new scripts are added). So the version is detected by behaviour, because
the module exposes none to read: `\p{Cn}` asks whether the two sides agree about which code points
exist, one disagreement settles it, and the scan is exhaustive so a skew cannot be missed by sampling.
On a skew the oracle skips and says why; matching versions run it unchanged — verified by bypassing the
detector, which brings back the full 10 and 44.

`make python-test PYTHON=<gate venv>` now runs 160 tests green. That documented path had never passed
at all: `python -m venv` on 3.12+ ships no setuptools, so it died building the extension long before
reaching the oracle.

## Two pins, because a stopwatch cannot hold a fixed per-call cost

The regression at the top of these notes moved **none** of the 26 layout rows. A short `count_matches`
row was written to catch the next one, and **withdrawn**: there is no cheap `count_matches`. Seven
shapes measured between 185 and 245 ns per call, because the cost is not the scan — on the same 35-byte
miss, `search` costs 70 ns and `count_matches` 214, while `find_iter` costs 213. The two candidate rows
then calibrated at **6.2 % and 6.6 % noise floors, the worst two of 28**, against an effect worth about
6.5 %. A guard whose floor is the size of the effect reports the truth about half the time. The refusal
and its numbers stay in `bench_minimal.cpp` so nobody re-runs a null sweep to rediscover them.

So the shape is counted instead, at zero nanoseconds: `sizeof(program_view) <= 440` (that view is copied
on every `find_iter` and `count_matches` call, so growing it is a decision), and
`tools/check_percall_copies.py`, three claims about the counting walk. Both verified against sabotage —
the size assertion fires when a span is added; the shape check catches the exact regression, the policy
being switched off, the function being renamed, and a decoy `true` in the body.

## A month of work refused, with the measurement that refused it

A Shift-OR / bit-parallel matcher has the highest ceiling anything here has been offered. `make
bench-census` counts what it could actually take, **weighted by cost rather than by pattern count**,
under four conditions rather than three — the fourth being that Shift-OR steps one *byte*, so a
text-mode code-point class is not implementable at all. It gets under a quarter of the panel. It is not
the next train, and the file says so with the table.

## The tables did not move, and that is measured

**§A, paired against `v2026.8.14`'s own harness, three interleaved passes per leg:**

- **arm64** — REAL's worst row moves 5.43 %, while PCRE2 — *byte-identical code in both binaries* —
  moves **7.84 %**. The engine is below the noise floor of its own measurement, and that floor matches
  the 1.00×–1.08× inter-run amplitude this document already declares.
- **x86-64 (gcc 15.3, idle)** — eleven of twelve rows improve; the single positive median is
  **+0.06 %**. `std::regex`, also unchanged, sits at 2.19 %.

One reading is recorded and **not** claimed: `lookahead` measures −6.73 % on x86, negative in all three
passes. The sentinel it no longer builds is worth about 60 ns against a 950 µs call — three orders of
magnitude too small — so this is layout, and PCRE2's control on that host was too unstable (28 %) to
support a finer claim.

**§B**, five headline rows inside about 1 %: `words findall @100KB` 2.15×, `digits sparse` 12.28×,
`literal hit` 11.83×, `anchored miss` 0.90×, `date search` 436.09×. The sixth — `sub · dates with refs`,
already flagged unstable here — reads 55.66× and is again below its documented range. Its own harness
prints a point estimate outside its confidence interval on that row, which is a defect of the
instrument and not a measurement of the engine; it is reported rather than smoothed.

## Nothing else changed

No answer changes anywhere in this train, on any of the four bound surfaces. `fowler-compat`,
`exhaustive-compat` and the full local gate are green; line coverage 96.13 %. The gate's own skip ledger
now carries **one** entry instead of two — the Unicode oracle step runs for the first time, and what
remains is a check that an arm64 machine cannot execute at all.
