# v2026.10.14 — Resource limits set per pattern, in every binding

v2026.10.13 was tagged but never published: its 32-bit Windows wheel failed a test, which found the bug fixed
below. This release carries all of it.

A service that compiles patterns it did not write could lower REAL's resource limits only for a whole build, by
macro. Each pattern now takes its own limits where it is compiled, in C++, C, Python, Rust and Go, and a pattern past
one is refused with a category of its own.

## Added

- **`real::limits`, passed to `real::regex` and `real::regex_set`**: the program's instructions, a bounded repeat's
  count, the capture groups, the nesting, a lookaround's length, and the bytes the search's lazy DFA may cache. The
  defaults are the build's ceilings (the `REAL_MAX_*` macros); a limit may lower its ceiling, never raise it,
  except the DFA's memory. A pattern past a limit raises `regex_error` with the new `error_kind::limit`.
- **The lazy DFA's memory is each regex's** (`limits::dfa_memory`, 64 MiB by default), where it was one budget for
  the process. Past it the search finishes on the VM, still linear and exact. A copy of a regex keeps it.
  `sizeof(real::regex)` grows by 8 bytes; no per-call count moved past its stamp's tolerance.
- **C**: `real_compile_opts` and `real_limits` (versioned by its `size` field; a field left 0 keeps the build's
  value), reporting `REAL_ERR_LIMIT`. `real_compile` and `real_compile_ex` keep their classification: a pattern past
  a ceiling is `REAL_ERR_SYNTAX` there, as before. Additive: `REAL_ABI_VERSION` stays 1.
- **Python**: `real.compile(pattern, limits=real.Limits(...))`, and `real.error.kind` (`"syntax"`, `"unsupported"`
  or `"limit"`). No `fallback` delegates a pattern past a limit to `re`.
- **Rust**: `RegexBuilder::size_limit` now holds (it was a no-op), in bytes as the regex crate's, and
  `dfa_size_limit` is new. A pattern past a limit is `Error::CompiledTooBig`.
- **Go**: `CompileWith(pattern, Options{...})`; a pattern past a limit fails with an error wrapping `ErrLimit`.

## Changed

- **A pattern past one of the build's ceilings (a program too large, a repeat count, the groups, the nesting) is
  `error_kind::limit`**, where it was `syntax`. A lookaround longer than 255 bytes stays `unsupported`, so the
  Python and C++ fallbacks still delegate it.
- **Rust: `Error` has a new variant, `CompiledTooBig(usize)`**: a `match` on `Error` without a wildcard arm needs one
  more arm.

## Removed

- The process-wide lazy-DFA budget (`real::detail::lazy_dfa_byte_budget()`), a test seam no public API reached.

## Fixed

- **Python, on a 32-bit interpreter: a limit past what a 32-bit size holds is refused**, where it was cut to that
  width: `real.Limits(group_count=1 << 40)` read as 0, which stands for the build's own value, and compiled. Each
  value now saturates at the most its field holds, past every ceiling (refused), the DFA's memory, which has none,
  as much as an address reaches. The Go and Rust bindings take sizes of the platform's width and had no such cut.
