# v2026.10.15 — A wrong match around a literal longer than 16 bytes

## Fixed

- **A pattern `class+ <literal> class+` whose literal is longer than 16 bytes could report a match that does not
  exist** (since v2026.7.57). The search finds a required literal by its first 16 bytes, then, for this shape, walks
  the class runs on both sides of it instead of running the engine; the walk took the literal to end after those 16
  bytes and let the suffix class run absorb the rest. Where the 16 bytes recur one position later inside the
  literal, a start was found one byte back and a match reported: `\w+aaaaaaaaaaaaaaaaab\w+` (17 `a`s) matched
  `aaaaaaaaaaaaaaaaab` alone, which has no word character before the literal. It took a subject of 64 KiB or more,
  or a regex that had already searched (a `fullmatch` or `match` was enough) — in Python, `real.compile` hands back
  the cached pattern, so a later `search` could see it. The shape is now confirmed by the engine when its literal is
  longer than the 16 bytes the search keeps. Found by the differential fuzzer against `std::regex`.
