# v2026.8.4 — the walk stopped returning to the dispatcher for every match

One change carries this release, and it came from asking a question the profiler could not answer:
*where does the time actually go on the rows REAL loses?* Every answer said "the scan". The
measurement said otherwise.

Every match count, span and capture group is identical to v2026.8.3, on both ISAs.

## 71 % of those rows was never the scan

Hold a class and its bytes fixed, and vary only how often a match must be emitted:

| pattern | ns/B | matches | |
| --- | ---: | ---: | --- |
| `\p{sc=Han}` | 7.590 | 66 672 | one match per code point |
| `\p{sc=Han}+` | **2.181** | 1 | the same bytes, one run |
| `\p{L}` / `\p{L}+` | 7.601 / **2.186** | 66 672 / 1 | |
| `[a-z]` / `[a-z]+` | 9.301 / **2.111** | 157 146 / 42 858 | |

The inner scan is ~2.2 ns/B. The other **71 %** is the return path — `run()`'s route dispatch,
`fill_span_slots`, and the iterator's re-entry — paid once per match, which for a single-code-point
pattern is once every three bytes.

So the walk now fills a small span buffer **inside** the route and hands out buffered spans,
re-entering the engine once per four matches instead of once per match:

| | arm64 | x86-64 |
| --- | ---: | ---: |
| `words [a-z]+` | 2.225 → **1.163** | 2.877 → **1.708** |
| `digits [0-9]+` | 1.381 → **0.845** | 1.758 → **1.089** |
| `[à-ÿ]+` | 3.390 → **1.572** | 8.183 → **3.336** |
| `\p{sc=Han}` | 5.556 → **3.326** | 9.246 → **5.974** |
| `\p{L}+` | 4.075 → **2.880** | 6.144 → **4.269** |
| `\w+` (mixed-script) | 3.010 → **2.295** | 5.236 → **3.686** |
| `\p{scx=Cyrl}` | 4.169 → **2.654** | 9.221 → **6.578** |
| `\p{N}+` | 2.108 → **1.876** | 5.526 → **4.460** |

Against PCRE2-JIT — the only engine this project still loses rows to — `words` goes from 1.05× to
**2.00×** on arm64 and 1.89× to **3.76×** on x86-64, `digits` to **1.70×** / **3.33×**, and `[à-ÿ]+`
(**1.31×**) and `\p{scx=Cyrl}` (**1.01×**) cross ahead for the first time in that table.

**What it costs, and it is in the published tables rather than omitted from them:** `fields` +3.4 %
arm64 / +7.4 % x86-64, `date` +5.6 % on x86-64, `.` +7 %. Those are routes the batch does not serve,
or serves badly — `[^,]+` averages 6.3 bytes per match, so there is nothing to amortise.

**Correctness is decided once per walk, not per match.** Eligibility excludes every shape the batch
loop does not reproduce: leftmost-longest, a `\b`/`\B` wrap, the maximal-run window guard, a `{k,}`
minimum, the trailing-lookaround walk, and constant evaluation. A differential compares **every span**
— not just counts — across 442 (pattern, subject) pairs spanning ASCII, 2-, 3- and 4-byte members,
malformed bytes, empty subjects and a run past the lazy-DFA floor, against the same walk with the
route seams disabled: zero divergence. It earned its keep immediately, catching a one-byte-subject
crash the moment the second filler was wired.

## A 22-range script class was on the wrong side of a threshold

`\p{sc=Han}` interns 22 code-point ranges against a `cp_hi_range_threshold` of 32, so every high code
point took a binary search instead of the sparse two-stage table. That constant stood at 32 on the
strength of a measured quasi-tie — and re-measured, the two classes that straddle it pull opposite
ways: `sc=Han` wants the table (**10.713 → 9.147 ns/B on x86-64, −14.6 %**), `scx=Cyrl` at 18 ranges
wants the search and loses 2.7 % on the table. The crossover lies between them, and the constant is
now that gap rather than either measurement.

A test comes with it, because the change moves a class onto a table that band had never used and one
character was its entire coverage. The new spread crosses all three encoding widths the table indexes
— including U+20000 — and the block edges an off-by-one would show at. **Every expectation was
cross-checked against PCRE2 in UTF+UCP mode rather than read out of REAL**, and the test says so, so
it cannot quietly be regenerated into a tautology.

## Four things were built, measured and refused

Each is recorded where the next attempt will look, with its numbers:

- **A table-driven UTF-8 decoder.** Sound and exactly equivalent — a differential over every 1- and
  2-byte sequence, comparing code point, length *and* validity, found zero divergence — and in an
  isolated probe a clear win on both platforms (`\p{sc=Han}` −13.3 %, `\p{L}+` −12.6 %). In the
  published harness it costs §A 4–13 % on rows that never call it. Three packagings were tried
  (256-entry table, 32-entry, either plus `noinline`); none survives.
- **Moving that decoder out of the blast radius.** A dedicated translation unit is foreclosed —
  this library is header-only — so the only lever is the inlining decision, and the two supported
  compilers want it in opposite directions: refusing inlining costs clang/arm64 `\p{N}+` **+44.4 %**.
- **A fourth span filler, for the whole-pattern `.` route.** The best of the four on clang/arm64
  (`.` over emoji, −58.8 %) and on gcc/x86-64 it gains nothing on its own row while taking back most
  of the byte filler's win. Two fillers is what this translation unit absorbs.
- **Instrumenting the benchmark harness to measure faster.** A runtime "time only REAL" switch —
  one function, two branches, a `getenv`, every engine still compiled and linked — moved `digits` by
  **12 %**. The instrument built to expose the codegen cliff fell off it.

## Two documents were lying, in REAL's disfavour

- **§E was stamped nine trains stale.** Its largest published deficit, `ident (\w+)_(\w+)` at
  113.178 ns/B on x86-64 against rust's 46.355, re-measures at **12.508** — rust 2.4× ahead becomes
  REAL 3.7× ahead. Both sides re-run, both ISAs: REAL leads **11 of 12** rows where the table said 8.
- **The site build broke on a deleted anchor.** A re-stamp removed the sentence a documentation page
  sliced on, and `full-local-gate` could not catch it because its docs-site step is skipped whenever
  `sphinx-build` is absent. `make check-site-anchors` now runs in the gate's cheap section, needs
  only the standard library, and requires every `:start-after:`/`:end-before:` under `docs/site` to
  resolve **exactly once**. Its own first version was blind to every MyST page and reported 18 clean
  anchors; fixed, it sees 29, and both failure modes were injected to prove it fails.

## Verification

805 tests, 0 failures. `exhaustive-compat` 3 218 434 cases, 0 serious divergences. Line coverage
96.61 % against the 95.0 floor. All 23 `full-local-gate` steps green, CI green across its jobs. Every
performance figure measured on both platforms — Apple M1 Pro under Apple clang 16 and the x86-64
devbox under g++ 13.3.0 — with the **shipped, unmodified** harness, as the minimum across runs, with
match counts compared before any ratio was printed.
