# v2026.9.9 — a DFA builds three times faster, and a mid-sized set fuses once it pays

A short train with two engine changes and no change to any answer. **Building a `real::dfa` is about
three times faster**, which speeds up `regex_set` construction and SciLex lexer construction. **A
`regex_set` of 24 to 55 members now takes the fused scan once it has been used enough**, instead of
never. The rest makes the test suite trustworthy on shared CI runners. Every change is compatible.

## Performance

- **Building a `real::dfa` is about three times faster.** The subset construction closed, completed
  and looked up a successor set for every state and byte class, though the successor depends only on
  the list of NFA positions it starts from; each distinct list is now closed and placed once. Moore
  minimization allocated a signature per state per round; it now sorts a flat table. The fused DFA of
  32 patterns builds in 3.1 ms instead of 9.5, 55 patterns in 4.3 instead of 12.1 (x86-64, g++ 13.3,
  -O2), with the same states. SciLex lexers build about twice as fast: its Python grammar 25.7 → 13.5 ms,
  its C++ grammar 5.7 → 2.9 (arm64, Apple clang).
- **A mid-sized `regex_set` takes the fused scan once it has been used enough.** One fused DFA scans a
  subject for every member at once. From about 24 members it costs less per subject than searching each
  member (1.4× at 24, 2× at 32, 4× at 55 members on log lines, x86-64), but building it takes a few
  milliseconds, more than a set built for one short subject gets back — which is why only sets of 56 or
  more built it, at construction. A set of 24 to 55 members now starts by searching each member and
  builds its fused DFA once its whole-subject `matches` calls have searched 1 MiB in total: by then the
  searches cost about what the build does, so the total stays within about twice the cheaper choice in
  hindsight. On the multi-pattern benchmark, a 32-pattern set now reads 480 MB/s where it read 195. The
  answers are the same either way; a set shared by threads builds once; region searches and `is_match`
  neither count nor build. A set of 56 members with fewer than 56 DFA-eligible ones takes this path
  instead of never fusing.

## Tests

- A test that held Unicode word boundaries on ASCII text to 1.8× the ASCII mode by the clock read 2.84×
  on a shared runner for a correct build. It now counts the searches the DFAs hand to the VM (none on
  ASCII) beside a witness that makes the count move. The ratio tests that still time two sides alternate
  them within each round, so a clock that drifts weighs on both.
- The ThreadSanitizer harness gained a wave in which eight threads cross a set's fused-build budget
  together.
