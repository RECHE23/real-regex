# v2026.10.4 — counts that do not hand out, regexes that warm up, bindings that cross once

**`count_matches` counts what a batched fill buffered without handing each match out**, which is what the
benchmark tables measure: the class and code-point rows run 16–54 % faster. **A regex used many times now
builds what one call alone could not repay**: a `match()` on a one-pass pattern with groups goes through the
one-pass table once the regex is warm, and a regex only ever searched on short subjects pays for the
inner-literal route once those subjects add up. **Short subjects go to the Aho-Corasick automaton without a
density sample.** **Python, Go and Rust take the engine's routes and cross into it less often**: Python's
`match`/`search`/`fullmatch` get the routes a C++ search gets, Go's `FindAll` and `ReplaceAll` cross cgo once per
batch, and Rust's single-shot queries run one search. The benchmark tables are re-stamped on both ISAs.

## Fixes

- **A regex's first build keeps the inner-literal warm mark** (d975ce8). After a short first call, the build a
  later call made cleared the mark that call was about to read, so the 4 KiB warm floor never applied: a fresh
  `\w+@\w+\.com` searched once short then four times over 6–48 KB, 909–990 → 834–838 µs (arm64).
- **The code-point class routes keep their own width** (c2042f2, a revert): sharing it cost Apple clang 16 on
  arm64 17 % on `[^,]+` (2.20 → 2.57 ns/B), found by the re-stamp of 2026-10-05.
- **`benchmarks/duel/run_duel.py` removes the corpus file each measurement wrote** (6ee2dad): a pass of the duel
  left about forty files, 1.1 GB over a few re-stamps.
- **A capped `replace`, `split`, `real_replace` or Python `sub`/`subn`/`split` stops at its cap** (b19c0b5)
  instead of searching one match past it, which on a sparse subject is the whole rest of it: `(\d)x` replaced
  once over 200 KB scans 200 004 bytes where it scanned 400 006.

## Performance

- **`count_matches` counts the spans a batched fill buffered** (fa6da56) instead of handing each out through the
  iterator: instructions over a log −25 to −39 % on `.`, −18 to −27 % on `[a-z]+` (GCC 13, 14, 15, clang 19);
  §A arm64 `single` 4.14 → 1.92 ns/B, `words [a-z]+` 1.18 → 0.78, x86-64 `single` 3.39 → 2.20. `find_iter` is
  unchanged.
- **A warm regex's anchored `match()` fills its groups through the one-pass table** (227063b): −35 to −56 %
  instructions per call once built, on all four compilers. The table is built on the 8 193rd anchored match of a
  regex, so a regex matched a few times never pays its build.
- **Short subjects that add up to the inner-literal floor's budget build the route** (fdc8a58): a regex only
  ever searched on short subjects stayed on the bounded backtracker; `(\w+)=(\w+)` over a 95-byte log line costs
  1 026 instructions a search once built against 19 953 (clang 19 arm64). The build is paid once 64 KB of such
  subjects have been searched.
- **The Aho-Corasick gate sends a subject shorter than its sample to the automaton unsampled** (7626056):
  searching a log line by line with 12 to 24 alternatives, 600 → 79 µs, 310 → 60, 1 774 → 93 (arm64, Apple
  clang 16); a fresh regex searched once on such a line −5 to −10 %.
- **The VM fills a DFA-proved window's groups anchored at its start** (eff6987): one 20 000-byte match of
  `(\w+)(\d+)` −28 to −32 % instructions; find_iter over a log on group patterns that reach the window −1 to −3 %.
- **A two-run group fill whose runs share one class does not walk the prefix run past the literal** (724c956):
  the duel's `ident` row, whose groups 2026.10.2 made right, −9.1 % instructions (GCC 15) and −5.6 % time on
  arm64; a `static_regex` walk no longer arms a lazy-DFA filler it cannot use.
- **Three fillers stay out of the batched walk's dispatch** (b587c6e): GCC builds of the class and alternation
  walks −1.4 to −3.6 % instructions, `dog` in the duel −11 %; clang unchanged.
- **A one-pass table's no in `fullmatch` is the answer** (6e5e5ae): a fullmatch of `(\w+)@(\w+)\.(\w+)` failing
  at the end of a 4 KB subject 118.7 → 11.8 µs. **The one-pass table takes the Tier-B program already built**
  (2be35cb), one byte program fewer per regex with a position assertion. **The refill after a spent subject is
  marked unlikely** (e50655f), which gave clang back 9 % on the dense class routes.

## Bindings

- **Python.** `match`, `search` and `fullmatch` take the routes a C++ search takes (8b69212): `[a-z]+(?=,)`
  655 → 182 ns. A region's default end costs nothing (38a72cf): `match()` missing over 100 KB of accented text
  131.7 → 0.16 µs. `finditer` no longer builds an end iterator per step (8d3c3ca): 3.86 → 1.31 ms over 88 KB;
  a `sub` that replaces nothing returns the subject itself, as `re` does.
- **Go.** A query passes the subject's own memory to C (2a2423f): `Match` with a hit at the start of 1 MiB
  22.5 → 0.13–0.36 µs. `FindAll` crosses cgo once per batch of 64 matches (bb8717c) and `ReplaceAll` expands
  every match in one call (0db6f49): −27 to −63 % and −43 to −53 % over 19 KB.
- **Rust.** A single-shot query is one engine search (4628739): `is_match` of a literal at the start of 1 MB
  37.4 → 0.05 µs.
- **C ABI, additive** (`REAL_ABI_VERSION` stays 1): `real_find_all_regexp` writes Go's regexp match sequence in
  batches over one scratch state, and `real_expand_all` splices a whole match sequence's expansions with the
  template parsed once (35d98ac, 075bdb8).
