# v2026.7.49 — hardening pass: two correctness bugs found before users

A **hardening-pass** release: public-surface oracles and contracts (true RE2
differential, frozen C ABI golden, TSan core) landed and **found real bugs**
before they reached users. No new performance claim — the one engine change that
touches a measured path **restores** the v7.47 `\p{}` baseline after a naive
cache-key fix would have destroyed it (A/B: ~78× regression avoided).

## Headline correctness

### 1. `cp_hi` cache poisoning (live in v7.47 / v7.48) — the serious one

The thread-local sparse table for high code points (`cp_hi`, v7.47 — used by
`\p{}`, dense `\w`/`\d` classes, mixed classes like `[\w€]`) was keyed by a
**pointer into the program's `cp_ranges` buffer**. That cache outlives any single
`regex` object. After destroy, the allocator can **reuse the same address** for a
*different* class; a later membership probe then returns the **wrong sparse
table**.

Symptom (deterministic on long test binaries, e.g. macos-clang CI): high
codepoints can **false-match** (e.g. 😀 treated as a member of `[\w€]` after a
prior dense class such as `\p{So}` was destroyed). Found by the euro empty-alt
finditer pin after a differential CI failure, then root-caused as cache
identity — not "environment flake."

**Fix:** key the cache by a **content fingerprint** (FNV-1a of the ASCII bitmap
+ every range), computed **once at class intern** and stored on
`cp_class.fingerprint`. Match-time only loads a `uint64` (same O(1) shape as the
old pointer key) so the v7.47 `\p{}` hot path is preserved. Dual-ISA A/B (x86
3-way: v7.47 vs naive per-codepoint FNV vs fingerprint-once): `\p{L}+` CJK
recovers ~7.2 ns/B; naive per-codepoint hashing was ~78× slower. ASCII
class-loop flat.

Regression: `cp_hi_cache_not_poisoned_by_destroyed_program` (poison `\p{So}+` →
destroy → `[\w€]` must not match 😀) + euro finditer pin (UTF-8 + escape forms)
+ corpus seed `fuzz/corpus/ci_finditer_euro_empty_alt`.

### 2. `GlobalReplace` empty-abut (RE2 drop-in, live in v7.48)

`real::compat::re2::GlobalReplace` dumped `find_iter` matches raw, so a nullable
pattern like `a*` on `"aa"` rewrote the trailing empty abutting the previous
match end (`##` vs RE2's `#`). **Fix:** skip a zero-width match whose start
equals the previous accepted match end (RE2 empty-advance policy). Legitimate
non-abutting empties (`a*` on `"bbb"` → `#b#b#b#`) unchanged.

Found by the new **true libre2 differential** (`make fuzz-re2`). Regressions in
`test_re2_compat` + corpus `fuzz/corpus/re2_gr_*`.

## Hardening infrastructure (now continuous in CI)

| Net | Role |
| --- | --- |
| `make fuzz-re2` | drop-in vs **true** libre2 (verdict/span/Replace/QuoteMeta/Set); can-fail inject; CI installs libre2 |
| RE2 10/11 portability | `re2::StringPiece` for FindAndConsume (Ubuntu apt vs Homebrew) |
| `make check-capi-abi` | golden **generated** from `real_capi.h` (enums, flags, 17 `real_*`); preflight CI |
| Flag cross-check | `test_capi_abi.cpp` pins `REAL_ERR_*` / `REAL_MODE_*` / `real::flags` bit values |
| Euro pin + seed | permanent regression for empty-alt + high-cp class finditer |

TSan core (`make tsan-core`) remains in the fuzz job from the prior train.

## Who should upgrade

- **Everyone on v7.47 or v7.48** who uses `\p{}`, dense Unicode classes, or mixed
  classes with high code points (`[\w…]` with non-ASCII members): the cache
  poison can produce **silent wrong matches** after regex churn in the same
  thread.
- **RE2 drop-in** users of `GlobalReplace` with nullable patterns (`*`, `?`,
  empty groups).

## What this is not

- Not a performance release: no new §A/§E wins claimed; cp_hi fingerprint-once
  **restores** 7.47, it does not beat it.
- Not a thin one-line patch: two user-facing correctness fixes + continuous
  oracles on the public multi-channel surface.
