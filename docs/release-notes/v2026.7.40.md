# v2026.7.40 — REAL speaks Go

A Go binding — `bindings/go/`, cgo over the frozen C ABI — plus a correctness fix to that ABI
found while building it.

## A Go binding

`bindings/go/` (module `github.com/RECHE23/real-regex/bindings/go`), v0.1, linux-x86-64 and
macOS-arm64 (Windows/MSVC and cross-compilation are explicitly out of scope for this version —
see the module's own README). cgo over `bindings/c/real_capi.h`, sources vendored into the
module (the go-sqlite3 pattern: a module fetched via `go get` has no access to the rest of the
monorepo) — generated, not hand-copied: `make go-vendor` regenerates from the source of truth,
`make go-check-vendor` is a CI drift gate (regenerate, then diff against the committed tree).

An idiomatic `regexp`-style surface — `Compile`/`MustCompile`, `FindAllIndex`,
`FindSubmatchIndex`/`FindAllSubmatchIndex` (an unset group normalizes to Go's own `-1,-1`, not
the C ABI's raw sentinel), `NumSubexp`/`SubexpNames`, `ReplaceAll`, and `RegexSet` (no `regexp`
equivalent — mirrors the Python binding's own native `RegexSet`) — plus what `regexp` (RE2)
cannot do at all: `FullMatch`, bounded lookaround, and possessive quantifiers, all with REAL's
linear-time guarantee intact. `regexp.Compile` rejects lookaround and possessive patterns
outright at compile time (confirmed empirically in the test suite) — REAL is a strict syntax
*superset* on the RE2-compatible core, so an existing `regexp` user migrates without rewriting,
then gains access to constructs they could not express before.

**The one thing to know before migrating**, and the module's README leads with it: `\w`, `\d`,
and `\s` are Unicode-aware by default here (Python `re` parity), where `regexp`'s are ASCII-only
by default. `\w+` on `"café"` matches all 5 bytes under this package; under `regexp`, it matches
only `"caf"` (`é` is simply not `\w` under RE2's default ASCII scope). Neither side is a bug —
found and pinned as its own dedicated test while writing the very first byte-offset differential
against `regexp`'s stdlib output, which is exactly why it made it into the README's first
paragraph rather than a footnote.

`EngineVersion` exposes the vendored C++ engine's own version (e.g. `"2026.7.40"`), read
directly from the vendored `real/version.hpp` — intentionally decoupled from this module's own
semver (`bindings/go/vX.Y.Z`, Go's Semantic Import Versioning; a CalVer major baked into the
import path would force a breaking import-path change every year, which the tag-prefix scheme
exists to avoid). No tag is cut in this release — `bindings/go/v0.1.0` on this commit is a
separate, manual decision.

Cold build (empty module cache, first-ever `go build`): ~8.2s on arm64, ~14.6s on
native x86-64 linux (a prior QEMU-emulated measurement, ~29s, was correctness-only and
discarded as a timing number). Both cached solid after the first build.

## C ABI: `(NULL, 0)` is a valid empty subject everywhere

Found live while writing the Go binding: `real_match`, `real_count_matches`, `real_sub`,
`real_set_is_match`, and `real_set_matches` rejected `text == NULL` unconditionally, even at
`len == 0` — while `real_find_iter`/`_at`/`_between` tolerated a null, zero-length subject just
fine. A Go `[]byte("")` has a nil underlying pointer, so the first natural implementation of an
empty-text call hit this asymmetry directly.

Convention adopted, stated once in the header: `(NULL, 0)` is now valid on every `(text, len)` /
`(repl, repl_len)` pair in the ABI — the natural representation of an empty slice in Go, so a
binding never needs a throwaway allocation just to say "nothing." Only a NULL pointer paired
with a *nonzero* length is still an error. A behavior change, not a signature change: a caller
that never passed NULL sees nothing different; a caller that did previously got `-1`
unconditionally and now gets correct empty-subject semantics.

## Verification

C-ABI fix: dedicated `(NULL,0)` coverage in `test_capi.c` (plus the still-an-error
`NULL`-with-nonzero-length negative case) and in `fuzz_capi.cpp` (unconditional every
iteration, not left to the fuzzed byte-carving — ~19.5k runs clean, 0 crashes); `rust-test`
100% (the additive-strict compat proof).

Go binding: 31 tests (the D0 spike's 22, plus a submatch/named-group/unset-group matrix,
`RegexSet` basic/invalid-pattern/empty-set/idempotent-close, and `EngineVersion`'s shape
check), `go vet` clean, `-race` clean, on both CI legs (linux-x86-64, macOS-arm64). The
vendoring anti-drift check was tested by deliberately trying to fool it in both directions:
editing the *vendored copy* directly is invisible (regenerated from source before the diff —
correct behavior, not a hole) and editing the *real source* (`include/real/version.hpp`) is
caught and blocked (`check-vendor` exits non-zero with the diff shown), confirmed independently
on both the primary machine and a second host.

`full-local-gate`: 18/18, 590 C++ tests / 52711 checks / 0 failed, coverage floor holds.
