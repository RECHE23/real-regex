The lazy-DFA arc lands: the general-search fallback used by patterns with no dedicated fast path
(`[a-z][a-z]+`, and anything else that reaches `pike.hpp`'s lazy-DFA block) is thinned end to end — three
separate cuts, each measured before moving to the next — plus IL-FUSION closes the inner-literal route's
own remaining gap for fixed-width neighbors (`\d{4}-\d{2}-\d{2}`-shaped patterns), reaching near-parity
with PCRE2-JIT on a line that trailed it 4× at the top of this train.

## Performance: the lazy-DFA arc (LEVIER-A) + IL-FUSION

Three cuts, applied in sequence to the same route, each verified before the next was attempted:

- **A1 — bounds-only.** When the lazy-DFA route already has the match span and the pattern is groupless
  (`slot_count <= 2`), the one-pass extractor's per-op table walk is skipped entirely — it exists to fill
  capture groups this shape does not have.
- **A2 — anchored-from-candidate.** When the pattern has a sound first-byte prefilter, `next_candidate`
  already knows every position a match could start; the reverse-DFA pass that recovers the start is
  redundant and is skipped, in favor of a new anchored forward walk (`lazy_dfa::anchored_end`) seeded
  directly at the candidate. A false candidate (a valid first byte whose pattern does not actually
  continue) advances one candidate at a time, not one byte — the same skip-after-failure argument the SIMD
  fast paths already use.
- **A3 — the lean munch.** Once `find_iter` has warmed a search up, the small state set a pattern like
  `[a-z][a-z]+` actually visits is already fully cached. `anchored_end`'s byte loop now reads the
  transition and priority-cut tables directly (two flat loads per byte, accept tracked against a local),
  falling back to the full construction/caching machinery only on a genuine cache miss.

Combined (`[a-z][a-z]+` on an English-word corpus, cumulative A1 → A3): **x86 17.0 → 7.44 ns/B (2.3×)**,
**arm64 13.5 → 6.1 ns/B (2.2×)**. Each step's own commit carries its individual before/after and the gates
that verified it (`lazy_dfa_route_disabled()` differential, exhaustive-compat, matrix4d, coverage) — the
numbers here are the rollup, not a re-measurement.

Separately, **IL-FUSION** closes the inner-literal route's remaining gap for patterns whose literal has
plain fixed-width neighbors on both sides (`\d{4}-\d{2}-\d{2}`-shaped, but as `[0-9]` byte classes — the
fusion needs `fixed_shape`, which a Unicode `\d`/`\w` shorthand does not qualify for): the whole span
verifies in one arithmetic pass (`match_byte_klass_run`) instead of reverse-DFA + forward-DFA +
one-pass extraction. `date {4}-{2}-{2}`: **x86 2.75 → 0.80 ns/B (3.4×)**, **arm64 1.93 → 0.52 ns/B (3.7×)** —
against PCRE2-JIT, this line moves from **0.23×** (a 4× loss) to **~0.83-0.94×** (near-parity, ISA-
dependent).

### Honesty

Missed targets are said plainly here too, matching the pattern the 7.26 rollup set:

- **date is not yet flipped.** IL-FUSION's own target was a line that beats PCRE2-JIT outright (a "flip"
  from the 0.23× loss); it lands at ~0.83-0.94× instead — a large, real gain, but PCRE2's JIT still edges
  it out on this shape.
- **A3 gained ~12% on arm64, short of its own target.** With the byte-walk reduced to two flat loads and an
  accept-local check, the arm64 bottleneck for this pattern was no longer lazy_dfa's own per-byte bookkeeping
  (the residual A3 targeted) — it had already shifted to what sits around each `anchored_end` call for a
  short-average-match pattern (the `run()` dispatcher's own branch cascade, `next_candidate`'s inter-word
  skip, per-match iterator bookkeeping), none of which was A3's scope.
- **matrix4d's `core_may_win` exception (A2) is documented, not masked.** Disabling the inner-literal route
  on a sparse `\d{4}-\d{2}-\d{2}` corpus now falls through to A2's faster anchored loop instead of
  `confirm_at`'s reverse-DFA/one-pass machinery — the fallback got faster, not the route slower. A genuine
  finding (IL's own machinery could likely adopt the same anchoring for `klass_cp` fixed-shape patterns,
  a future fiche), pinned with a narrow, commented exception flag rather than a loosened threshold or a
  skipped row.

## Fix

- **A libc++-only `regex_token_iterator` no-match divergence, isolated and pinned, not papered over.**
  libc++ yields an empty token sequence on a zero-match subject only when the maxsplit list is literally
  `{-1}` alone; any longer list gives libc++ an empty sequence too, where `real::compat`'s
  spec-and-libstdc++-consistent behavior yields the leading unmatched segment. Documented in
  `docs/COMPATIBILITY.md` (`regex_token_iterator`), with a version-variant fuzzer skip mirroring the
  existing empty-text skip and a dedicated `real`-only regression test — no suite-wide deactivation.
- Hardens a latent unguarded write in the lazy-DFA reverse start-finder (`reverse_dfa::step` cached a
  transition after an `intern()` that can flush mid-call — the same trap `lazy_dfa::step` already
  guarded). Present since the lazy-DFA route shipped; no production-budget reproducer is known (caught by
  a coverage test using a reduced state budget).
