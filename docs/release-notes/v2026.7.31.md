# v2026.7.31 — linear-time fix + Linux word-extraction speedup

Patch release. Restores the "linear time, always" guarantee for a class of
patterns that had silently regressed to quadratic search time, and lands the
work accumulated since 7.30: faster word extraction on Linux wheels, an
inner-literal density gate, an opt-in profiling substrate, and a word-boundary
factorization. No API changes.

## Fix (P0) — quadratic search on unbounded-reach patterns

A pattern with a sound first-byte prefilter but an unbounded reach past that
byte (`a.*b`, `a.+b`, `.*needle`, and similar shapes) could take **O(n²)** time
on an adversarial haystack: the lazy-DFA route (A2, anchored-from-candidate)
re-scanned from each first-byte candidate all the way to the end of the
haystack before trying the next one.

Restored to **linear** time: once a candidate's own miss proves the pattern's
reach is unbounded (its scan reached the end of the haystack without a dead
state pruning it early), the route hands off to the existing single-pass
forward search instead of retrying candidate by candidate. Guarded by a new
deterministic linearity test (a compile-gated work counter, not wall-clock) so
this class of regression cannot ship again unnoticed.

Affects any `search` / `find_iter` / `findall` call on a pattern with this
shape. Result-invariant — same matches, just no longer quadratic.

## Perf — word extraction on Linux wheels

`\w+`, `\b\w+\b`, `\d+` (Unicode word/digit shorthands, text mode): the
code-point membership test for non-ASCII bytes is now an outlined, cold path
on gcc builds (gcc/manylinux — the Linux PyPI wheels), where gcc was not
inlining the previous nested closures. Measured **~20–25%** faster on this
pattern family on Linux; macOS/clang wheels are unaffected by construction
(the outline is gcc-only — clang was already inlining the original shape
well).

Density-gated inner-literal routing also lands: a dense-match corpus (e.g.
`(\w+)_(\w+)` on `id_42`-style text) no longer pays reverse-DFA overhead once
candidates are frequent enough — **~6.8×** on that shape.

## Internal

- Opt-in profiling substrate (`make profile-sample`): a route-tick counter and
  a two-pass (clean timing / instrumented attribution) JSONL + Markdown grid,
  for targeted profiling without touching the shipped build.
- Word-boundary (`\b`/`\B`) handling in the class-loop fast paths factored to
  a single shared policy (no behavior change).

## Honesty

The P0 fix closes a real gap against the project's own "linear time, always"
claim — REAL was never exponential on this shape (no backtracking, so classic
ReDoS was never possible here), but the polynomial slowdown was real and
shipped in 7.30. Nothing to claim beyond "fixed."
