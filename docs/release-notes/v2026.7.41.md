# v2026.7.41 — issue #3: WordBoundary and Alternation, plus a fuzzer-found hang

Four commits, all triggered by [issue #3](https://github.com/RECHE23/real-regex/issues/3), an
external benchmark report showing REAL losing badly to `rust::regex` on three pattern shapes —
WordBoundary (790x, 98ms vs 0.12ms), Alternation (8.7x), and Literal (6.9x). This release closes
the first two. A third, unrelated bug surfaced while fuzzing the Alternation fix — severe enough,
and squarely of the "hangs the engine" kind, that it shipped in the same train rather than wait.
A fourth commit is a follow-up to the Alternation fix itself: an x86/gcc codegen regression its
first cut introduced, caught before release and fixed at the root.

## WordBoundary: the `{n,}` counted-quantifier fast path

`\b\w{4,}\b`-style patterns were falling off the class-loop fast paths entirely. The `{n,}`
desugaring (`compiler.hpp`'s `emit_repeat`) emits `n-1` mandatory copies of the atom followed by
a self-looping copy — a shape the byte-class and codepoint-class loop recognizers only ever
matched at `n==1` (a bare `X+`), never for `n>1`. Extended both recognizers to count `k>=1`
identical copies before the self-loop, closing the gap generically rather than special-casing
`{4,}`.

Measured on this project's own `benchmarks/duel/` harness: the WordBoundary gap against
`rust::regex` closes from ~14.5x to ~1.8x; on the x86 leg, `\b\w{4,}\b` itself dropped ~94%
(~17x faster than before the fix).

## Alternation: the `small_set` cap was capped below its own runner's ceiling

`run_alternation`'s SIMD masked-block scan (a first-byte-set prefilter, `pike.hpp`) has always
supported up to 8 distinct first bytes. The *recognizer* that arms it (`prefilter.hpp`) only ever
enumerated up to 4 — a 5-to-8-distinct-first-byte alternation, exactly issue #3's own example
(`cat|dog|fish|bird|fox|bear|wolf|deer|hawk|frog`), fell all the way through to the
un-accelerated bitmap loop. Raised the cap to match: ~1.6x on issue #3's own alternation. Found as
a byproduct of a design spike into whether a full Teddy/Aho-Corasick engine was warranted here (it
wasn't — see the spike's own NO-GO; this small, safe fix was the piece worth shipping now). Honest
note: this closes part of the Alternation gap, not all of it — a future Aho-Corasick engine would
close more of it for pure-literal alternations specifically, but `small_set` stays useful
independent of that: it is a general 5-to-8-first-byte prefilter, not only an alternation
mechanism, so it is not a throwaway fix an AC engine would obsolete.

## A severe, pre-existing hang: `\w{k}`-style repeated classes

Fuzzing the Alternation fix turned up something unrelated and considerably worse: `\w{42}a}`
hung the engine for 60+ seconds — confirmed unbounded, and confirmed pre-existing (100%
reproducible on an unmodified baseline, isolated via a clean worktree A/B). Root-caused to three
independent, compounding costs, all in the one-pass builder's handling of a large Unicode class
repeated a fixed number of times:

1. **`onepass::minimize()`'s Moore partition refinement had no round cap.** A repeated large
   class floods thousands of one-pass nodes per copy and forms a *chain* needing ~k rounds to
   converge — quadratic in k, unbounded as k grows.
2. **A redundant O(node-count x program-size) reallocation** in the node-flooding loop: a scratch
   buffer was re-allocated and re-zeroed on every node processed, when the recursive walk that
   fills it already restores it to all-zero between iterations on its own.
3. **`build_byte_program` gave every occurrence of a repeated class its own freshly-built UTF-8
   trie**, even though every copy of a `{k}`-repeated `\w` references the identical interned
   class. Fuzzing with this project's own `make fuzz` (`-timeout=10`, the real constraint) showed
   even `\w{15}a` costing ~7 seconds under the sanitizer build, well before the one-pass builder
   was ever reached.

All three now have calibrated caps: exceeding any of them declines gracefully to the Pike VM
(always correct, just without the one-pass capture-extraction fast path), matching this file's
own established safety-net pattern. Worst case measured across k=5..1000 against the real
sanitized `make fuzz` build: ~1.4 seconds, down from 21+ seconds (and unbounded beyond that).

## A layout regression in the Alternation fix, caught before release

The Alternation fix's `small_set` array grew from 4 to 8 bytes, in place, inside `pattern_hints` —
right before the `greedy_class_loop*` fields the class-loop fast path (the single most common fast
path) reads on every call. Growing an unrelated field ahead of hot ones shifts their offsets and
their cache line; `small_set` itself is written once at compile and read only by the alternation
route, so it never needed to sit in that hot prefix at all. The struct already carried the
discipline for exactly this risk — `stop_set`, a few fields down, is explicitly commented "placed
last so it never shifts the hot fields' offsets" — the Alternation fix's first cut didn't follow
it. Moved `small_set` next to `stop_set`: pure field reordering, no logic touched, the alternation
cap stays at 8 and its gain is unaffected. Caught by this project's x86 leg before any release
went out; on x86/gcc, the regression (as much as +40% on a common class-loop shape) is eliminated,
not shifted elsewhere.

## Verification

WordBoundary fix: 2777+308-check parity matrices against an oracle, meta-seam differential
coverage, fuzzer (5x100k), 2-ISA A/B.

Alternation fix: 82-check Python `re` oracle parity (icase, search/match/fullmatch, the
4-9-distinct-first-byte boundary including zero-match), meta-seam differential coverage, 2-ISA A/B.

Hang fix: full test suite unchanged; a fresh Python `re` oracle parity sweep across the new
work-cap boundary; targeted tests for each of the three caps (`onepass_minimize_work_cap_declines`,
`onepass_byte_program_size_cap_declines`, the pre-existing node-cap test, plus
`onepass_repeated_class_no_longer_hangs` proving the fallback still matches correctly); a clean
5x100k fuzzer campaign; direct re-verification against the real sanitizer-instrumented `make fuzz`
build across k=5..1000; A/B confirming zero regression on already-fast one-pass patterns.

Layout fix: pure reordering, no logic change — full test suite and both the alt-fix and hang-fix
Python `re` oracle parity scripts re-run clean against the reordered struct; 2-ISA A/B confirming
the regression is gone, not displaced, and both this train's gains (WordBoundary, Alternation)
are unaffected.

Coverage top-up for this train's own new paths (the P1 min-check boundary, byte-class and
Unicode cp-class, with and without `\b`; each of the one-pass builder's three cap-decline
branches; the Alternation fix's 5-8-member `small_set` interior, not just its ends): closes
95.60% to 95.64%. Every remaining uncovered line in the four touched files is a pre-existing,
already-documented, structurally-unreachable defensive guard predating this train (e.g. an
`assert`-style bound a hand-crafted malformed program would be needed to hit) — not a gap in this
release's own logic.

`full-local-gate`: 18/18, coverage 95.64% (floor 95.0%).

## What's next

Issue #3's third finding — Literal (6.9x against `rust::regex`) — is not addressed in this
release; it did not surface a correctness bug the way the other two did, and needed its own
investigation not yet started. Queued for a follow-up train, along with the R5 UTF-8 prover,
D2.1, and — per this release's own Alternation note — a full Aho-Corasick engine for literal
alternation.
