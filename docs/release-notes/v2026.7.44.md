# v2026.7.44 — WordBoundary peel (issue #3 residual): IL + single-atom `\B`

Closes the remaining WordBoundary performance gap from
[issue #3](https://github.com/RECHE23/real-regex/issues/3) the light way — **without** an
assert-aware lazy-DFA. Two residual shapes that still fell to the general Pike VM after Arc B /
P1 / 7.41–7.43 get dedicated routes by extending peels that already existed:

1. **`\b\w+@\w+\b`** (and lead-only / trail-only variants) — top-level `\b`/`\B` used to decline
   the required-inner-literal extraction entirely (`anchor` → decline), so the pattern never
   armed the `@` memmem + reverse-confirm path that bare `\w+@\w+` already takes. Extraction now
   peels a single optional lead and trail word-boundary, records `prefix_skip` so the reverse
   prefix excludes the assert (asserts are not byte-DFA-eligible), and `confirm_at` re-checks
   boundaries on the full program.
2. **`\B\w` / `\B\d`** (single atom, no `+`) — `resolve_class_wb_hints` used to unarm any class /
   cp-class shape that carried `\B`. That was correct for **maximal** runs (`\B\w+`): the
   skip-whole-run scanner is unsound for mid-run `\B` starts (`\B\w+` on `"hello"` → `"ello"`).
   Single-atom shapes only advance one code point on a failed lead check, so the wrap is sound —
   they now arm with `wb_lead = 2` and the existing B-2 runtime check.

**Deliberately still general:** maximal `\B\w+` / `\B[a-z]+` (and mixed `\b…\B` on a maximal run).
Correctness over a fragile mid-run scanner; the DFA-assert-aware arc (D1b) is **not** taken —
the peel closed the measured residuals.

No changes to `lazy_dfa` / `reverse_dfa` / `forward_end`.

## Measured (dual-ISA, interleaved fixed binaries)

| case | arm64 (Grok) | x86-64/gcc (superviseur) |
| --- | --- | --- |
| `\B\w` vs general | ~4.2× | **−82% (~5.6×)** |
| `\b\w+@\w+\b` (match-bearing) | ~2× | fast-path armed (no-match memmem-`@` short-circuits; match gain ~2×) |
| `\b\w+\b` (existing peel) | flat | −0.2% (noise) |
| witness `[a-z]+` | — | **−9.8% incident gain** |
| `fields [^,]+` / `wplus \w+` | flat | −0.4% / −0.9% (noise) |

Zero regression on x86 — the opposite of 7.43's disclosed `fields` +39% front-end alignment
exception. The peel adds no code-bloat to `pike_vm::run()`'s translation unit.

## Proof

- Meta-seam: `seam_run_inner_literal_wb` (`\b\w+@\w+\b` and lead/trail-only) + `\B\w` / `\B\d` in
  `seam_run_cp_class_loop` — route-auto vs hints-blanked general VM, group-aware.
- Peel / resolve unit tests updated for the new `\B`-single-atom policy; IL extract pins
  `prefix_skip` / wb hints on `\b\w+@\w+\b`.
- `make test` green; project line coverage ≥ 95.7 (local coverage-check).
- Go binding re-vendored for the engine + version bump.

## What this is not

Not a re-stamp of §A absolute figures (the witness cell is now *more* conservative where it
gained). Not the assert-aware lazy-DFA design spike (D0/D1b) — that path is closed as overkill
for these residuals.
