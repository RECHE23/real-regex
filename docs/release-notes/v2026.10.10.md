# v2026.10.10 — Fixes from the October audit, and a DFA munch that says when it is final

An audit of the engine and its compatibility layers against Python's `re`, PCRE2, libre2, Go's `regexp` and
libc++/libstdc++ `std::regex` found wrong answers in four places of the engine and two of the drop-in layers.
They are fixed here, each with a property test and its sabotage. One addition: `real::dfa::munch`, the munch a
streaming lexer needs, which also says whether text after the subject could change it.

## Fixed

- **`can_extend` with a lookaround that reads past it.** `a(?=$)` on `"a\n"`, `(?<=a\b)` on `"a"` and
  `a(?=\b)` before a code point cut short answered that no text could change the match, when more text did. A
  lookahead's window now counts the code point an assertion at its end reads, and a lookbehind holding an
  assertion that looks right stays open at the end of the text. A fuzz of the property (a `false` is never
  contradicted by an extension) found 6 to 11 such cases per seed before, none after, over 1.45 million checks.
- **`(?i)` no longer case-folds a shorthand in a class, as `re` does not.** `\W` holds U+0345, a non-word mark
  that folds to iota, so `(?i)[^\W\d_]` (the usual "letters" class) left out ι, Ι and U+1FBE, and `(?i)\w`
  matched U+0345. Literals, ranges and `\p{…}` properties still fold (the properties as the `regex` module
  folds them). Checked against `re` on every code point.
- **A `regex_set` of 56 or more patterns that each compile always builds.** A fused DFA past its bound threw
  `real::dfa_error` from the constructor (and from `compat::re2::RE2::Set::Compile`, which promises not to
  throw); the set now walks its members, as a mid-sized one already did.
- **`(?a:\B)` and `(?a:\b)` at the edge of a fixed-width pattern** were tested with the program's word-ness on
  the fixed-shape route: `(?a:\B)[0-9A-Za-z_]` matched in `"éa"`. The route now declines such a boundary. The
  route differential generates scoped boundaries from now on.

### `real::compat` (the `std::regex` drop-in)

- **POSIX bracket classes in the ECMAScript grammar.** `[[:alpha:]]`, which the C++ standard adds to its
  ECMAScript grammar, read as a set of literal characters. A class is rewritten as its ASCII ranges and stays
  on the linear engine. A class under `icase`, and `[[.x.]]` / `[[=x=]]`, which libstdc++ and libc++ read
  differently, are std's: the strict policy rejects them, `policy::fallback` delegates them.

### `real::compat::re2`

- **RE2's reading of the syntax.** `\w \d \s` are ASCII and `\b \B` read ASCII word characters (a class member
  folds before it is negated, as in RE2); `[[:alpha:]]` and the other POSIX classes are classes; `$` without
  `(?m)` is the end of the text; `GlobalReplace` steps past an empty match as RE2 does. A random ASCII
  differential against libre2 diverged on about 600 of 36 000 cases per seed; it now diverges on 1 to 3, all
  in the documented empty-iteration family. `fuzz-re2` checks every rewritten class over every code point
  against libre2. One orbit differs: under `(?i)`, İ and ı fold with i and I, as in `re`.

## Added

- **`real::dfa::munch(subject, offset, memo)`**: the answer of `match` and whether text after the subject
  could change it — false once the walk died, ended in a state no byte leads on from, or was stopped by the
  memo on a stretch walked to a death. It costs nothing over `match`. SciLex's streams use it and run at about
  1.5× the time of a whole-text tokenize, where they ran 55–264× slower.

## Documentation

- The empty-iteration rule (`(?:a?|b)+` on `"ab"`: `re` (0,1), REAL (0,2)) is stated as REAL runs it, with
  the portable form, and pinned in C++ and Python; three pages that described it differently agree. The Go
  binding's README lists it as a sixth difference from `regexp`.

## Benchmarks

The tables are not re-run. The matching routes changed only where a scoped word boundary declines the
fixed-shape route; `dfa::match` was measured neutral within noise (SciLex tokenize, arm64).
