# v2026.10.8 — Bindings that keep what they borrow, and read their arguments as their models do

A corrective release for the bindings, from an audit of each against its model library. **Go: a method no
longer lets the collector free its `Regexp` mid-call**, which returned wrong answers under GC pressure. **The C
ABI checks every match's spans in `real_expand_all`** and lets no C++ exception out of an entry point.
**Python: `Match`, `finditer` iterators and `Pattern` objects held by their own subject or pattern are
collected**, and five places that raised another exception than `re` raises now raise `re`'s. **Rust: a start
inside a character, and `${` templates, behave as the `regex` crate's.** The engine is unchanged.

## Fixes

- **Go: a method keeps its `Regexp` or `RegexSet` alive until its C call returns** (5058529): a finalizer
  could free the compiled program while a call still read it once the receiver was otherwise unreachable, as in
  `MustCompile(p).MatchString(s)`. Reproduced at 400 wrong results out of 400 calls under a collecting goroutine,
  and none with the fix. `Close` must still not run during another call; the documentation now says so.
- **C ABI: `real_expand_all` validates each match's spans at the stride it reads them** (96b961b): only the
  first match's were checked, and `nspans * nmatches` could overflow. `real_sub` and `real_expand` turn a C++
  exception into an error return instead of letting it cross the C boundary.
- **Python: a `Match`, `finditer` iterator or `Pattern` held by its own subject or pattern is collected**
  (f884b49): a `str` or `bytearray` subclass holding what was made from it leaked both, since none of the three
  reported its references to the cycle collector. A `Match` over an exact `str` or `bytes` stays off the
  collector, so the common path allocates as before.
- **Python: `Match.lastindex` names the group that closed last in a loop** (5e0b976): `(?:(a)|(b))+` over
  `"ba"` reported 2 where `re` reports 1.
- **Python: errors and argument kinds as `re` has them** (db9f26b, 0ae4025): a lone surrogate written in a
  pattern raises `real.error` at its position, so `fallback=True` delegates the pattern to `re`; `\g<a-b>` and
  other malformed template group names raise `real.error` instead of `IndexError`; `m.group()` reads an
  `__index__` object as a number, an out-of-range `int` as no such group and an unhashable argument as
  `TypeError`; `real.compile(re.compile(...))` compiles the pattern again instead of raising `TypeError`. The
  `IndexError` for an unknown template group name read `'%.*s'` on Python 3.11.
- **Rust: a start inside a character searches from the next boundary** (e5e1a3e): `find_at` and the other `_at`
  queries with a start between a character's bytes now match the `regex` crate. An unclosed `${` is literal and an
  empty `${}` expands to nothing, in `str` and `bytes` templates, as in the crate.

## Documented

- **Lone surrogates in a Python subject or `str` template** raise `UnicodeEncodeError`, where `re` matches
  them: the engine reads UTF-8, which has no encoding for them. Pinned in both directions
  (`div_surrogates` in the differences from `re`).
- **A template group name follows Python 3.12's rule on every version**: on 3.11, `re` still accepts `\g<+1>`
  with a `DeprecationWarning`.

## For contributors

- `tools/sabotage.py` rebuilds the C++ test binary when a C ABI source is sabotaged (519e5cf).
