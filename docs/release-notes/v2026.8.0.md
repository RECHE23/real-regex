# v2026.8.0 — routing decided by the subject, and allocation counts that stop depending on the pattern

Four measured performance changes and one correctness fix that gcc caught and clang did not. The
theme, if there is one, is that three separate places in this engine were deciding at compile time
something only run time can know — and each of them was measurably wrong about it.

Matching is unchanged. Every span, capture group and match count is identical to v2026.7.63.

## Aho-Corasick was chosen by counting branches, which cannot predict anything

The multi-literal route was taken whenever an alternation had at least 12 branches. That gate had a
`\warning` on it saying it selected on the wrong property, and this train turned the warning into an
instrument and then into a fix.

The automaton scans at a flat **3.15 ns/byte** whatever the haystack. The memchr cascade it replaces
runs anywhere from **2 µs to 135 µs** on the *same* pattern and the *same* subject length. Nothing
about the pattern says which of those two you get; only the subject does. At 24 branches all four
test subjects took the automaton, and one with no matches paid 12.92 µs where the cascade costs 2.00.

Routing now samples candidate density at the search start, once per haystack:

| subject | arm64 before → after | x86-64 before → after |
| --- | ---: | ---: |
| no match | 12.92 → **2.21 µs** (5.85×) | 13.57 → **3.63 µs** (3.74×) |
| one late match | 13.50 → **2.29** (5.90×) | 13.68 → **3.75** (3.65×) |
| match-dense | 26.58 → 27.42 (0.97×) | 36.42 → 36.33 (1.00×) |
| false starts everywhere | 13.00 → 13.38 (0.97×) | 13.74 → 13.73 (1.00×) |

Sparse subjects gain 3.7–5.9×; dense subjects keep the win the automaton was added for, at 3 % on
arm64 and no measurable cost on x86-64.

**The rule is a product, which nobody predicted.** The crossover moves by 3× between 12 and 24
branches — the cascade tries branches in order, the automaton does not — so what is roughly invariant
is `(candidates per 1000 bytes) × branch_count`, not density. A density threshold alone would have
been right at exactly one branch count.

**The constant is the measured minimum, and that is a consequence rather than a preference.** The
two platforms disagree by 1.7× about where the crossover sits (~615 on x86-64, ~1050/795 on arm64).
But every alternation past the branch floor took the automaton *before* this change, so switching too
early cannot be worse than what it replaces, while switching too late forfeits a win that already
exists. Rounding below the earliest crossover on either platform therefore cannot regress anything,
and the disagreement stops being a tuning argument.

**The branch threshold is kept**, against the plan recorded for it, and demoted from gate to domain
floor: there are no measurements below 12 branches, because the threshold itself prevented taking the
route there. Deleting it would extend the route to shapes nobody has measured.

## The capture pool grew by doubling during the search

A general-VM search over `\w+@\w+` made 13 heap allocations. Their sizes were 4, 8, 32, 16, 64, 128 —
a doubling ladder, not work. `basic_capture_pool::reset()` assigned its three vectors and let
`allocate()` grow them by `push_back` mid-search, so every capture-carrying search re-walked the same
growth curve from zero. Reserving a block budget first takes it to 5.

The number that matters is not 5 but its variance. The allocation probe read the general route at
**min 4 / median 7 / max 17** and now reads **5 / 5 / 5**: how many allocations a search performs is
a property of the *route* instead of the pattern. Timing follows — `((\w+))` −20.0 % on arm64 and
−15.0 % on x86-64, `\w+@\w+` −9.4 % / −6.1 % — measured as the minimum across five alternating rounds
per arm, against `[a-z]+` as an untouched gauge that reads 0.0 % / +2.3 %.

## Named-group enumeration allocated a map to answer one question

`group_name(i)` built a `std::map` of every named group on every call. The fix is an indexed walk
over the program's own name table: **6–15× faster** and allocation-free. It is *not* a complexity fix
— the walk is still linear in the number of groups, and the release notes say so because the
temptation to call it one is exactly how a linear API becomes quadratic again later.

The same change had to be written twice: the first cut bound a `const&` to a `named_group` living in
a temporary `span`, which clang accepted and **gcc rejected** under `-Werror=dangling-reference`. The
local gate is clang-only, so a `gcc-check` step now compiles the engine headers under gcc's
diagnostics — the class of defect that only one compiler names.

## The Aho-Corasick automaton was rebuilt on every search

Not new to this train — it landed alongside the routing work and belongs in the same story. The
automaton lived on the VM state, and a state is fresh per `search()`, so crossing the branch
threshold rebuilt it every call: **29.5 µs and 584 heap allocations** where a 3-branch alternation
below the gate cost 0.14 µs. Cached per regex, that is **12.6 µs and zero allocations**.

## Instruments, because two of the above were found by hand years late

- **`make alloc-probe`** — heap allocations per dispatch route, over composed patterns. The invariant
  it asserts is that allocation count belongs to the route, not the pattern: every non-general route
  must be flat zero. It would have named the rebuilt automaton on the day it was written.
- **`make route-probe`** — which dispatch routes composed patterns actually reach. Currently **6 of
  20 unreached**, each either dead or gated more narrowly than its author believed. **[Erratum,
  2026-08-01, added after release: that sentence is wrong, and wrong in the direction that flatters
  the tool.** All six were the probe's own blind spots, not findings about the engine. Three needed a
  subject past the 512-byte lazy-DFA floor against a corpus that topped out at 41 bytes; two needed a
  whole-pattern `.` or negated class, which free composition emits about once in 2300 draws; one
  needed a delimited possessive whose loop is `*+` rather than `++`, which is what the recognizer
  requires. The probe reports **0 of 20** now and no dead route was ever found. A tool that cannot
  reach a route is not evidence the engine cannot either — see `benchmarks/route_probe.cpp` and
  commit `27d0b81`.]
- **`make ac-regime`** — the four Aho-Corasick subject regimes plus a crossover sweep, with match
  counts compared across arms before any ratio is printed.
- **`benchmarks/measure.hpp`** — time XOR allocations, a compile error if you ask for both. The
  allocation counter replaces global `operator new`, which is not inlinable and inflated one
  measurement by **2.8×** in a figure that was published as a property of the code. That mistake was
  made three times in one session, twice after the hazard had been written down.

## Hardening

**A `static_regex` shape was proved at compile time and never run.** Chasing 0.04 points of coverage
found that `basic_capture_pool<static_vec<…>>::reset` was the one instantiation in the whole suite
that no test executed: a test declared two 2-group `static_regex` objects, asserted on them only
through `static_assert` — constant evaluation, where the pool is a compile-sized array the compiler
folds away — and closed with a bare `EXPECT(true)`. The runtime instantiation was compiled and never
called. Now exercised over `std::string` the compiler cannot see through; coverage 95.33 % → **96.81 %**.

**The docs-site gate could be turned red by its own previous run.** Breathe's record of the Doxygen
compounds it last read survives in the gate's output directory, so a struct deleted weeks earlier
made the next run die before it read a single source. The gate clears its scratch directories now.
The mechanism is recorded as *inferred* — four attempts to reproduce it on demand all failed — with
one measured fact behind it: Doxygen's XML output is incremental and does not remove compounds for
entities deleted from the code.

## Disclosed, not chased

- **§A is unaffected by construction**, not by measurement: its table contains no capture-carrying
  pattern, and its one alternation row (`the|fox|dog`) has three branches, below the routing floor.
  §E's `captures/*` rows are where the capture-pool change would show, and they were **not** re-run
  this train — that is a criterion campaign against the rust crate, and it is not this train's claim.
- **The arm64 crossover product is not one level but two** — ~1050 for 12–18 branches and ~795 for
  20–24, each to within 1 % across four rounds. A real discontinuity, reproducible and unexplained.
  It does not affect the constant, since the minimum is on the other platform either way, but it is
  the one place the routing rule rests on a shape nobody can justify yet.
- **Below 12 branches is unmeasured.** The domain floor is held by absence of data, not by evidence.
- **A routing test cannot be a stopwatch.** The first cut asserted the guarded run beats the forced
  one by 2×: true at 5.9× optimised, false at 1.4× under ASan/UBSan, where additive instrumentation
  dilutes the advantage of a route whose whole merit is skipping bytes. It turned the sanitize leg red
  while the engine was correct. The decision is observable directly now; the timing evidence lives in
  the benchmark, where a slow machine cannot fail a build.

## Verification

792 tests, 345 287 checks, 0 failures. Line coverage **96.81 %** against the 95.0 floor. All 23
`full-local-gate` steps green, and CI green on 29 jobs including the `linux-gcc` leg that covers the
gcc-only diagnostics, `windows-msvc`, `linux-arm`, `macos-clang`, MISRA, both fuzzers, conformance and
six Python matrices.

Every performance figure in this document was measured on **both** platforms — arm64 under clang and x86-64 under g++ 13.3.0, the toolchain that builds the manylinux wheels — as the
minimum across alternating rounds, with an untouched row read as a gauge before any delta was
believed. Where the two disagree, both are printed.
