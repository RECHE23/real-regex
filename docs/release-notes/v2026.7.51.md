# v2026.7.51 — fidelity train: parser/compat correctness + RE2-parity campaign

A **correctness** release. No performance claims — this train touches the
parser and the two compat layers (`std::regex` drop-in, RE2 drop-in), not the
matching engine's hot paths. Three fuzzer-found fixes to dialect/compat
fidelity, and the RE2-parity campaign that closes six of the seven measured
gaps against real RE2 (`libre2` 11.0.0); the seventh (duplicate group names)
plus a sub-edge discovered while closing `\x{...}` (surrogate code points)
are stated as deliberate, documented divergences.

## Corrections (3)

1. **ecma-gate: the ECMAScript grammar accepted native-only syntax**
   (`4f29958`). Possessive quantifiers (`X*+`/`X++`/`X?+`/`X{n,m}+`), the
   atomic group `(?>...)`, Python-style named groups `(?P<name>...)`, and
   `(?#...)` comments are constructs from REAL's *native* dialect — none of
   them exist in ECMAScript (V8 raises `SyntaxError` on all four). Under
   `flags::ecma` the parser used to accept them anyway and run REAL's native
   possessive/atomic semantics behind the `std::regex`-compatible API, which
   can silently diverge from what an ECMAScript engine (or `std::regex`
   itself) would do. Found by `fuzz-compat` on the pattern `[^a]?+` (plus a
   trailing raw byte): real matched the class as possessive (`pos=3/len=2`)
   while libstdc++ parsed the same text as `([^a]?)+` (`pos=2/len=3`) — a
   silent span divergence, not a thrown error. Fixed by gating all four
   constructs on `!is_ecma()` at their parse sites; under `flags::ecma` they
   now fail as "unknown extension" (or hit the existing multiple-repeat
   check, for the possessive suffix), matching V8 and both standard
   libraries. The native dialect is unaffected — all four keep working there.
   Seed committed as `fuzz/corpus/compat_ecma_possessive`.

2. **nullable-captured-repeat: `regex_replace`/iterators diverged on
   `$N`/`m[N]` for a nullable group under a quantifier** (`9262643`, pinned
   per-stdlib by `af4fe97` and documented by `cd0f2b9`). A capturing group
   that can match empty, sitting under a quantifier — `(ab|)+a` — is a
   documented REAL/std divergence class: REAL's traversal captures the
   group's last *non-empty* iteration (the RE2/Rust/Go lineage), while an
   ECMAScript backtracker captures the trailing *empty* one. The compat
   routing only checked whole-pattern nullability before deciding whether to
   run REAL's own traversal or fall back to `std::regex`, so a pattern like
   this — nullable only in a captured sub-group, not as a whole — still ran
   on REAL's traversal for `regex_replace` and the match iterators, and
   `$N`/`m[N]` came out wrong relative to `std::regex`. A new
   `pattern_hints::nullable_captured_repeat` bit, derived by an AST walk in
   `compiler::compile()`, now routes `regex_replace` and the iterators to
   `std::regex` for this class (conservative over-approximation: assertions
   and lookarounds count as nullable, so over-routing is safe). `regex_search`
   and `regex_match` are deliberately left untouched — routing search to
   `std::regex` would forfeit REAL's linear-time guarantee on every
   `(x|)+...` pattern — so a narrower residue (`m[N]` on a bare `search`)
   remains, documented in `docs/COMPATIBILITY.md`. That residue itself
   turned out to be stdlib-variant, not universal: MS STL keeps the last
   *non-empty* iteration (agreeing with REAL) where libstdc++/libc++ keep the
   trailing empty one, caught by the Windows CI leg and pinned per-stdlib
   (`_MSVC_STL_VERSION` branch) rather than hardcoded to one library's
   behavior.

3. **`without()` truncated the compat flag-scope stack to `uint8_t`**
   (`b11fd7e`, bundled with the `(?U)` feature below — found en route while
   testing it). A pre-widening vestige from when `real::flags` was 8 bits
   silently dropped any flag at bit 8 or above when a scoped `(?flags:...)`
   body popped its scope — including `flags::allow_raw_byte` (256), latent
   since 7.42 (the RE2 raw-byte-escape flag introduced that train): a scoped
   body like `(?i:\C)` could lose `allow_raw_byte` on exit from the `(?i:...)`
   scope. Exposed while wiring up `flags::ungreedy` (512, see below), which
   would have been dropped the same way. Fixed by widening the truncating
   cast to the flags' actual `uint16_t` underlying type; a
   `(?i:\C)`+`allow_raw_byte` regression is now pinned.

## RE2-parity campaign (6 closed, 2 by design)

A local measurement against real `libre2` 11.0.0 (66 RE2-valid constructs)
found seven ways `real::compat::re2` violated its own header contract
("compiles everything RE2 compiles"). Six are now closed, each with match/
extent parity *enforced* against true RE2 in `fuzz_re2` (not just
compile-parity):

- **`\p{Any}`** and **`\p{^Name}` caret negation** (`3f1cfa0`) — `\p{Any}` is
  an ECMAScript-conformant binary property (the full code-point range, no UCD
  table entry needed); `\p{^L}` strips the leading caret and XORs into the
  existing negation logic (gated `!is_ecma()`, since caret negation inside
  `\p{}` is Perl/RE2 syntax).
- **`\x{...}` braced-hex codepoint escape** (`ca1b410`) — shares the digit
  loop and surrogate/`>10FFFF` validation with `\N{U+...}`; gated
  `!is_ecma()` (ECMAScript's braced form is `\u{...}`, not `\x{...}`; the
  existing two-hex `\xHH` byte escape is untouched).
- **`\Q...\E` literal quoting** (`216dd33`) — gated `!is_ecma()`; matches
  RE2/Perl semantics measured directly against `libre2` (quantifier binds to
  the last quoted character, unterminated `\Q` runs to end of pattern, empty
  span is grammar-invisible).
- **`(?flags-flags)` global flag removal** (`0afbfac`) — the global (non-scoped)
  inline-flags prefix was add-only; it now parses an optional `-removed` run
  too, e.g. `(?i-s)A.B`, matching the existing scoped `(?flags-flags:...)`
  parser. Mid-pattern global flags remain rejected (a separate, unmeasured
  RE2 gap, out of scope for this train).
- **`(?U)` ungreedy-swap inline flag** (`b11fd7e`) — new `flags::ungreedy`
  (512): swaps the default quantifier greediness (RE2's `(?U)`), resolved
  entirely at parse time into each repeat node's `lazy` bit (an explicit `?`
  suffix still re-inverts, so `(?U)a+?` stays greedy); scoped forms
  `(?U:...)`/`(?-U:...)` and the constructor flag all work through the
  existing flag-scope stack. Semantics measured against `libre2` on eight
  forms, including the possessive interaction.

Two entries remain in the ledger — the seventh measured gap (duplicate group
names) and a sub-edge discovered while closing `\x{...}` (RE2 accepts
surrogates unvalidated) — stated as **deliberate, principled divergences**
where REAL is intentionally *stricter* than RE2, not unimplemented gaps
(`c09a9bb`, which also rewrites `re2.hpp`'s header contract to say this
precisely and fixes a second inherited inaccuracy — RE2 does *not* reject
`\p{}` outright, it accepts `\p{L}`/`\p{Greek}`; the actual REAL superset is
the namespaced forms `\p{gc=…}`/`\p{sc=…}`/`\p{scx=…}` and the UCD binary
properties RE2's grammar lacks):

- **Duplicate capturing-group names** (`(?P<n>...)(?P<n>...)`) — RE2 tolerates
  them; REAL rejects them because its named-capture lookup is by-name and
  would be ambiguous with a repeated name (capture-safety).
- **Surrogate code points** in `\x{...}`/`\u`/`\U`/`\N` (e.g. `\x{D800}`) —
  RE2 does not validate them; REAL rejects them through the same
  Unicode-scalar validation it applies to every code-point escape.

Both are enforced as the only two entries in `fuzz_re2`'s KNOWN-GAP ledger —
a regression on either reddens as a subset-violation, not a silent pass.

## DX

- `make help` is now an auto-generated, workflow-first menu (a "Start here"
  section plus per-role groups) driven by `## ` doc-comments on each target,
  vendored as `mk/help.mk` (`33696db`, `2ab45ae`).

## Nets

- `fuzz_re2`'s differential harness now tells its two failure directions
  apart: REAL accepting more than RE2 (superset — on-contract) stays
  non-failing telemetry, while REAL *rejecting* something RE2 accepts
  (subset — a violation of the drop-in's promise) is now `note_bug` unless
  explicitly allow-listed as a KNOWN-GAP; a `can-fail` case proves the subset
  direction reddens when the allow-list is suppressed (`2ef1c6f`).
- `full-local-gate` gained a Go leg (`go-check-vendor` + `go-test`, skipped
  with a warning when Go is absent) — the one component previously absent
  from the local gate, so an `include/` change that stales the vendored Go
  tree is now caught locally instead of only in CI (renumbered 18→20 steps,
  `9812566`).
- The nullable-captured-repeat compat edge (correction 2 above) is
  stdlib-variant, not universal: pins now assert compat routing against the
  *local* std only, and the golden residue lock records each stdlib's own
  edge separately (libstdc++/libc++ vs MS STL).
