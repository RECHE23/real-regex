# v2026.8.16 — a public DFA that answered no

**`real::dfa` could return a wrong answer.** That is why this ships. Subset construction
walked a range-for over the state vector while `find_or_add` appended to it, so `end()`
was captured once. Any pattern whose construction *discovers* states — most of them —
compiled to a one-state automaton. Under `-O2`, `match()` reported no match on input the
pattern accepts. Under a sanitizer it was a heap-use-after-free. The same constructor
builds the fused path of `real::regex_set`. If you construct `real::dfa`, or a
`regex_set` of at least `fused_min_eligible` (56) DFA-eligible members, upgrade.

`real::regex` is not that constructor. It is a different machine (`detail::lazy_dfa` /
the Pike VM). A `regex_set` below the fused threshold never builds a `real::dfa` either:
it walks members through `regex::search`. The default match path of every binding
(`Pattern`, `Regexp`, `Regex`) is `real::regex`. Their `RegexSet` wrappers are
`real::regex_set`, so the same 56-member line applies there.

The 890 tests that stayed green through the defect were running a binary older than the
headers. `make test`, `sanitize` and `coverage-build` now refuse that.

## Also fixed, also user-visible

**`real::compat::re2` accepted a `float` it could not hold.** `Arg` parsed every
floating-point destination through `strtod` and narrowed with a cast, so
`FullMatch("1e40", …, &f)` on a `float` returned `true` and left the destination at
infinity. The conversion now matches the destination type, as RE2's does, and an
out-of-range value is refused.

**Python `Pattern` grew the protocol `re` already had.** `repr` prints the source
instead of an address. `copy.copy` / `copy.deepcopy` return the same object, where
they raised `TypeError`. A `Pattern` pickles by recompiling (a `Match` still does
not, like `re`). `real.error` fills `pattern`, `pos`, `lineno` and `colno`.
`Pattern[str]` / `Match[str]` exist for type checkers.

**Go `Regexp.String()` returns the source text**, like `regexp.Regexp.String()`. The
text lives on the Go value; `Close` does not clear it. A value copy of `Regexp` or
`RegexSet` still shares the C handle — unlike `regexp.Regexp`, `*r` is not a safe
clone — and `go vet -copylocks` says so at the copy site (`noCopy`, not a compiler
error).

## Guarantees this release adds to itself

Several gate steps reported success without measuring anything. `make lint` analysed
no shipped header; it now analyses 36 and prints the count. The vendored Go tree was
verified by regenerating it first, which proved determinism rather than freshness; it
is now compared without writing. Every one of these steps fails at zero units. The
stale-binary refusal above is the same class: the instrument, not the suite, was
blind.

A tool installed for one CI step does not go on `PATH` for the others. Putting the
Python 3.10 floor on `PATH` made `check-features-probe` die on `import yaml`.

## Documentation

The reference pages carry a contract instead of a bench log. Implementation notes and
measured figures moved to `//` comments; two checks fail if that voice comes back, or
if a published member is omitted from a curated page without a stated reason.
`design.dox` is a tour again rather than a journal. Machine names are gone from the
published documentation.

## Benchmarks

The tables in `docs/BENCHMARKS.md` still carry the `2026.8.15` stamp. They were not
re-measured for this release. Of the five engine commits the stamp names, the one
that can move a throughput row is `perf(inner-literal)` (`d0dc644`): the warm floor
now lifts once the build is paid, and the batched filler no longer consults a density
gate that cannot see completions. `fix(dfa)` and `fix(re2-compat)` change answers,
not scan cost. Treat the published cells as describing `2026.8.15`. The methodology
and the reproduction recipe stay in that file.
