# v2026.7.62 — the documentation becomes enforceable, and a lazy build stops being paid for nothing

A **documentation** release, a **correctness-of-record** release, and — in one accessor — a
**small behaviour change**, which is stated first because every previous release in this series
could open with "no behaviour changes" and this one cannot.

Matching is untouched. Every span, every capture group and every match count is identical to
v2026.7.61. The change is to what one accessor *reports*.

## The behaviour change: `compile_flags()` now reports the set in force

`real::regex::compile_flags()` (and `basic_regex::compiled_flags()` on both storages) used to
return the constructor flags OR-ed with the letters a leading global-flags group **added**, and
ignore what a `-removal` **cleared**:

```cpp
real::regex re("(?-i)a", real::flags::icase);
re.search("A").matched();   // false  — matching honoured the removal, always
has_flag(re.compile_flags(), real::flags::icase);  // was true, now false
```

The accessor and the engine disagreed, and only on this one case.

This is a fix to an incoherent contract rather than a change of intent. The accessor already
reflected inline **additions** — `(?i)a` with no constructor flag has always reported `icase` —
so it was never "the flags you passed in"; it was a hybrid of passed-plus-added, which describes
nothing. The only coherent reading is "the flags in force", and it failed that on removals alone.

Cause: the parser applied a removal to its own base scope, but only the added letters reached
`ast::inline_flags`, which is OR-ed across calls and cannot represent a removal. Removals now
travel in a companion field and are cleared where the effective set is built.

**If you depend on the old value**, you want the constructor argument you passed, which the
caller already has. Nothing in the C ABI exposes this accessor, so no binding surface moves.

## `(\w+)@(\w+)` first use reaches parity, and the cost was never where five passes had looked

`first_use/email` had been the one row where the `regex` crate led REAL, tracked down from
**21.3 ms** to 2.91 ms to 2.64× behind across five passes of making the one-pass table cheaper to
build. The sixth pass found that the table's construction was not the problem — building it *at
all* was.

The measurement that settled it was the capture-free twin. `\w+@\w+` has two capture slots — a
whole-match span and nothing else, so there is no capture for an extractor to fill — and it cost
the same **1487 µs** as its six-slot twin. `ensure_immutables()` built the one-pass extractor
alongside the byte program, so every route needing the cheap half paid for the expensive one,
whether or not it could ever consult it. Of a 1494 µs first search: byte program 331 µs,
extractor **884**, lazy DFA 117.

Built only where captures are actually extracted through it, guarded by its own identity flag:

| criterion row | REAL | `regex` | |
| --- | ---: | ---: | :--- |
| `first_use/email` | 604.53 µs | 601.81 | **parity** — the CIs overlap |
| `first_use/word_bound` | 7.73 | 269.85 | REAL 34.9× ahead |
| `first_use/no_match` | 5.97 | 170.87 | REAL 28.6× ahead |

Direct harness, both platforms: a first search drops **1490 → 573 µs on arm64** and
**1958 → 813 on x86-64**. `\d{4}-\d{2}-\d{2}` follows it from 296 to 167 — six `\d` occurrences,
and a no-match scan never extracts.

**Parity, not a lead.** The confidence intervals overlap ([595.8, 615.4] against [593.5, 612.5]),
so the defensible claim is that the gap is gone.

**The obvious way for this to be fake is for the cost to have moved rather than gone**, so the
scan rows were re-measured: `find/email` 46.52 µs against 46.20 recorded, `captures/email` 51.98
against 52.10, `find/no_match` 1.67 µs against the crate's 776 ns. All unchanged.

What nearly went wrong: `try_shared_lazy_dfa_search` extracts through the table from inside the
slot lock, so the naive split would have left it reading an empty optional and silently losing the
one-pass fast path — a regression wearing a win's clothes. It also cannot build the table where it
uses it, because that inverts the lock order `reset_shared_dfas` walks.

## Every entity in `include/real/` is documented, and the gate can finally say so

**895 Doxygen warnings to 0**, across every header. The comment form is uniform too: an object
takes a `/*! ... */` block, an attribute a trailing `//!<` — **317 members** reformed to it, with
two structural exceptions that are checked rather than trusted (a declaration whose initializer
spans hundreds of lines has nowhere to attach a trailing comment, and `//!<` is a single-line form
that cannot hold multi-line rationale).

The six generated Unicode headers were fixed **at their generators**, not by hand; all six
byte-identity regen guards still pass and every pinned total is unchanged.

## Four checks that could not see what they were for

The theme of this release, and the reason it is a release rather than a cleanup.

**`EXTRACT_ALL = YES` neutralised `WARN_IF_UNDOCUMENTED`.** The Doxyfile carried
`WARN_AS_ERROR = FAIL_ON_WARNINGS` and reported clean over 895 undocumented members, because
extracting undocumented entities as if documented leaves that warning nothing to fire on. The gate
measured nothing and read as proof.

**Doxygen never warns about an orphaned doc block** — a comment whose function was renamed or
deleted, which collapses onto the next declaration and describes something it does not document.
It renders one `\brief` and silently drops the rest. Three shapes were found: two `\brief` in one
block (13), a block cut mid-sentence (4), and two blocks stacked with no declaration between (8).
All three are now checked; none is auto-fixed, because deciding which declaration a paragraph
belongs to is a judgment and guessing would delete real prose.

**A stale XML made the style checker report clean** while eleven violations remained: it reads
Doxygen's own XML for member kinds, `make doc-check` runs the CI Doxygen inside Docker and does
not refresh it, and every entry whose line number had drifted was silently skipped. It now refuses
to give a verdict against an XML older than the headers.

**`version-check` cannot see benchmark staleness between releases**, because it compares version
*strings*. This release's own perf change closed a deficit `docs/BENCHMARKS.md` documented as open,
and the check reported clean. A companion now asks whether the engine changed *in substance* since
the figures were stamped — substance, because eleven of the last fourteen commits under
`include/real/` touched only comments, and a check that fires on all of them teaches its reader to
ignore it.

Each is proved in both directions — with a defect injected it fails and names the file and line;
restored, it passes — and `check-doc-style` runs in CI's preflight, not only locally.

## Documentation that had stopped matching the code

Found by audit and verified against the source before being touched, not taken on trust:

- **All five POSIX grammars** (`basic`, `extended`, `awk`, `grep`, `egrep`) were documented as
  routing to the std backend. They are translated onto REAL when the pattern translates — probed
  empirically, all five report `uses_real` and leftmost-longest bounds. `posix_longest()` also
  claimed it was set "only for a translated `extended`", and the umbrella header still described
  non-ECMAScript grammars as always delegating.
- **`(?ims)`** understated the contract in nine places across four headers: the parser accepts
  `i m s x a U` plus a `-removal` suffix, all six letters verified to compile and match.
- **`grammar_forces_std()`** described itself as the filter that sends POSIX grammars to std,
  while sitting *after* the translation attempt — a grammar reaches it only once translation has
  declined.
- **`regex_set::eligible_count()`** read as a count of DFA-eligible members but answers 0 whenever
  fusion is inactive, which its own test pins.

## Disclosed, not chased

- **`find/no_match` and `captures/no_match` stay 2.09×/2.05× behind** — a ratio on 1.6 µs against
  776 ns, so the gap is in ratio, not in substance.
- **`captures/word_bound` stays 1.82× behind**, `find/literal` 1.57×.
- **The AVX2 two-byte prefilter leg for x86 is still unwritten.** No public row currently demands
  it.
- **Only three `first_use` rows were re-measured**, one criterion group at a time and not under the
  interleaved A/B protocol §E.4's main table uses — which is why they sit in their own table there
  rather than becoming a column in one they do not belong to.
- **`check-bench-stamp` is local-only.** It reads git history, and CI checks out at depth 1; in a
  shallow clone it announces that it cannot answer rather than reporting clean.

## Verification

785 tests, 345 251 checks. Line coverage 95.59 % against the 95.0 floor (engine logic; `bindings/c`
is guarded by sanitize + fuzz instead). Sanitizers clean, ThreadSanitizer clean on the shared-immutables path
this release adds an atomic to (8 threads × 200 iterations, 1 862 400 hits), matrix-gate 0 red
cells, fuzz smoke clean, clang-tidy clean, MISRA 0, the six Unicode regen guards green, Go and
Python bindings green.

Captures verified byte-identical on the Tier-A, Tier-B (`\b`-wrapped) and non-one-pass shapes. The
documentation rewrite was proved to be comment-only: with comments and whitespace stripped, every
modified header is byte-identical to its pre-pass state, and every word missing from any doc
comment across all 36 headers is accounted for individually.

`full-local-gate` and CI green on the train, including the windows-msvc leg, plus the Docs and
Docs-site jobs.

## Notes

Nothing here changes what REAL matches. The linear-time / ReDoS-safe guarantee and the bounded
lookarounds are unchanged, and so is the matching API. The one observable change is
`compile_flags()`, described at the top.
