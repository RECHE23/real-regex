# v2026.9.7 — a tokenization is linear, not only a munch

This train ships three things a caller can use and one they must adapt to. **`real::dfa` tokenizes
in linear time**: a new `dfa_munch_memo` stops the rescans that made `a*b` beside `a` quadratic over
`"aaa…"`. **The C ABI hands a compile error's position over as a number**, and the Rust crate stops
parsing it out of the message. **The Go and Rust bindings close five gaps with the libraries they
stand in for.** And **`RegexSet::matches` in Rust now returns the `regex` crate's `SetMatches`** —
a breaking change, described below.

## Breaking: `RegexSet::matches` returns `SetMatches` (Rust)

`matches` returned a `Vec<bool>` indexed by pattern. It now returns `SetMatches`, the `regex` crate's
shape: iterating it yields the indices of the patterns that matched, ascending, from either end;
`matched(i)`, `matched_any`, `matched_all` and `len` (the number of patterns, not of hits) behave as
the crate's. Code written against the crate now compiles unchanged; code written against the old
`Vec<bool>` does not compile — a `bool` where a `usize` is used, or `m[i]` where `m.matched(i)` is
meant. **Cargo reads `2026.9.7` as compatible with `2026.9.6`**, so `cargo update` delivers the change;
the break is a compile error, never a silent one. `matched_ids` still returns the `Vec<usize>`.
`RegexSet::empty()` and `Default` are new. A test compares every `SetMatches` method with the crate's
over thirty set/subject pairs, the empty set and an out-of-range `matched()` included.

## `real::dfa_munch_memo`: linear tokenization

One munch is linear in the bytes it reads, but it reads until the automaton dies. With `a*b` beside
`a`, every position of `"aaa…"` rescans the rest of the subject looking for the `b`: lexing n bytes
cost n(n+1)/2 transitions. `dfa::match(subject, offset, memo)` answers exactly what
`match(subject.substr(offset))` answers and records every (state, position) a walk visited after its
last accept — none of them leads to an accept — so a later walk reaching one stops there (Reps,
*Maximal-munch tokenization in linear time*, 1998). Tokenizing costs O(states × length): **3n
transitions on that input**, counted exactly by `memo.transitions()`. Tests compare the memoized munch
with the plain one over lexing sequences and over offsets in random order.

SciLex, whose DFA-accelerated modes call `dfa::match` once per token, adopts it in its next release.

**Building a `real::dfa` is about ten times faster**, with the same tables. A profile of the Python
example grammar's automaton (348 states) put 80 % of its 167 ms in the subset construction's move,
which tested every NFA instruction for every state and byte class although the state sets are
sparse, and most of the rest in a linear search for known states. The build now walks each state's
set bits once for all its classes, shares epsilon-closures, and finds known states by hash: 167 →
16 ms for that grammar, 27 → 3.5 ms for the C++ one (2026-09-23, arm64, `-O2`). The discovery
order is unchanged; the nine example grammars' automata answer 20 000 random munches each exactly
as before. This is what lets SciLex try every mode for DFA acceleration by default.

## The C ABI reports where a pattern fails

`real_compile_ex` and `real_set_compile_ex` write the bare cause to `errbuf` and the engine's byte
offset to a new `err_pos` out-parameter — `(size_t)-1` when the failure has no offset, and on success.
`real_compile` and `real_set_compile` are unchanged: the ABI stays additive. The Rust crate calls the
`_ex` forms and no longer reads `regex_error at N:` back out of a 256-byte buffer; `Error::Syntax`'s
`pos` is the engine's number.

## Bindings

- **Rust:** `real_regex::escape`, with the `regex` crate's escaped set and so its output, checked
  over every ASCII character; `RegexSet` implements `Debug` as the crate's does.
- **Go:** `SubexpIndex` and `ReplaceAllString`, held to `regexp` by the ReplaceAll differential, which
  now compares both for every pattern, subject and template it sweeps.
- **Rust:** `clippy` runs over the crate, its tests and examples with every warning an error, in the
  gate and in CI. Its first pass found a `loop` whose every arm returned.

## Tests and CI

- **The C ABI shim was 37 % covered** by the instrumented binary, whose header said it sat under the
  coverage floor: `real_match`, `real_sub`, `real_expand` and the set queries ran only in the pure-C
  smoke. Each branch now has a case; 95 % of lines, the rest being catch clauses only an allocation
  failure reaches. A span check in `real_expand` that could not fire is gone.
- **A weekly long fuzz run** (`fuzz-long.yml`) gives the four fuzzers an hour each and keeps each
  corpus between runs; the per-push jobs remain 45–60 s smokes.
- **Every guard's self-test is proven condition by condition**: `tools/blind_guard.py` blinds each
  condition of a guard and names the ones its self-test does not notice; 294 conditions across the
  guards, each reddening its self-test.
- **The gate's lint step was red** on four test files under clang-tidy 22; fixed.

## Public statements corrected

Every performance figure on the README and the compatibility page now carries its date, its
instrument and its route. The compat layer's `replace` was said to be "6–17× faster" than
`std::regex_replace`; on the one measured case it is ~4× faster than libc++'s and **~0.75× — slower —
than libstdc++'s**, and a guard refuses a speed claim against `std::regex` that does not name the
library.

## Not claimed

No benchmark cell was re-run, and `docs/BENCHMARKS.md` keeps its `2026.8.15` stamp; see the
`CHANGELOG.md` entry. The memo's bound is counted in transitions, not timed; the plain `dfa::match`
is unchanged and every existing caller keeps its path.
