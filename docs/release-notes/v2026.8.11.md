# v2026.8.11 — the measuring instrument was wrong, and fixing it changed what shipped

This train's most consequential change is not in the engine. The method this project used to decide
whether a change helped — compile twice, compare — was calibrated against its own benchmark and found
to report **double-digit deltas on rows that provably cannot be affected**. Deleting 21 lines of
compile-time-only code moved `digits [0-9]+` by +16.7 %. Everything else here follows from having an
instrument that can tell a change from a coincidence.

## The instrument

`benchmarks/bench_layout.py` compiles the same source into several semantics-free layouts, pairs and
interleaves the two sides, and — the part that makes it honest — **calibrates each row's noise floor by
running a tree against itself**, where the true delta is zero by construction. `make bench-layout-null`
then `make bench-layout BASE=<tree> CAND=<tree>`.

It paid for itself immediately, three times, and twice against its author:

- It caught a systematic **+1 to +4 % positive bias in its own first version**, which ran side A's
  sweep and then side B's — the second was on a warmer machine. Interleaving collapsed the worst row
  from +3.9 % to +0.6 %.
- It **falsified its own first decision rule** ("agrees on K−1 of K draws"): on a true-zero change,
  `(?i)café` agreed 8 draws out of 8 at +3.4 %.
- It **falsified the rule this repository had been using** — "rows moving the same way on both ISAs are
  real work, rows disagreeing are placement" — because the impossible +16.7 % moved the same way on
  both. That rule is retired from `design.dox` §10.1 and from `BENCHMARKS.md`.

A design fault of its own is recorded rather than quietly fixed: the floor was a **maximum**, which
grows with sample size and so cannot converge (`digits` calibrated at 1.0 % from 8 readings and 6.0 %
from 24). It is now a 95 % quantile. Two claims made with the broken estimator are withdrawn in
`MEASUREMENT.md` §5, including this project's own "the floors span a factor of seventy" — with a
converging estimator the span is a factor of **seven**, and the row named as worst is in fact the best.

## Two instruments, because the harness is not shaped like a consumer

`bench_engines.cpp` links `<regex>`, PCRE2 and RE2 beside `real.hpp` and sits on the compiler's
per-unit inlining budget. A consumer compiles only `real.hpp`. `benchmarks/bench_minimal.cpp` is that
translation unit, and re-judging there **invalidated three of this train's own refusals**:

| row | four-engine harness | consumer unit |
| --- | ---: | ---: |
| `\w{2,}` | no row existed | **−38.1 %**, 24/24, REAL |
| `\p{L}{3,}` | no row existed | **−36.2 %**, 24/24, REAL |
| `\p{L}+` (the refusal's cause) | +4.9 %, then +7.6 % | **−0.3 %, indistinguishable** |

So: the consumer instrument decides whether a change lands; the harness decides what is published;
when they disagree both are reported. `MEASUREMENT.md` §5.5. This is not a licence to reopen every past
refutation — it is a second reason to re-check the ones that turned on small harness costs, one at a
time.

## What the engine gained

Seven routes crossed a full route entry **per match** where the class routes cross one per batch. Five
no longer do. Every figure below is x86-64, judged against measured floors, with the number of paired
draws agreeing:

| change | gain |
| --- | ---: |
| bare possessive `[a-z]++` → greedy selector (recognition-time redirect) | **−72.6 %**, 16/16 |
| `words [a-z]{4,}` — counted minimum, byte class | **−46.0 %**, 16/16 |
| `\w++` → code-point greedy selector | **−43.4 %**, 16/16 |
| `\w{2,}` — counted minimum, code-point class | **−38.1 %** (consumer unit), 24/24 |
| `\b\w+\b` — the dropped-`\b` class walk | **−28.6 %**, 16/16 |
| `\b[a-z]+\b` — a `\b` the recognizer could NOT drop | **−20.5 %** (consumer unit), 24/24 |
| `alt the\|fox\|dog` — fixed alternation | **−20.7 %**, 16/16 |

`alternation` **crosses ahead of PCRE2-JIT on x86-64 for the first time** (0.94× → 1.22×), and
`single [a-z]`, `words [a-z]{4,}`, `words [a-z]++`, `\b\w+\b` and `\w{2,}` are new rows — a route this
table does not measure regresses in silence, which also means no earlier stamp compares to this one.

**The cheapest changes were the recognizer redirects, and that is the transferable lesson.** A bare
`X++` is the same language as `X+` — possessive means "take the maximal run and never give it back",
and with nothing after the loop there is nothing to give back to. Arming the greedy selector instead
of a possessive one costs three lines at compile time and gained 72.6 %, after **three** runtime
implementations of the same idea were measured and refused for charging the Unicode rows 5 to 9 %.
When a fast route already exists for an equivalent shape, redirect to it at recognition time.

## What it costs, in full

On the published harness, arm64's Unicode property band pays for this train: `\p{sc=Han}`
2.312 → 3.156 (0.93× → 0.68×), `\p{scx=Cyrl}` 2.743 → 3.581, `\w+` 1.970 → 2.278, `[à-ÿ]+`
1.617 → 1.975; and x86-64's `words` 1.56 → 1.79 with `digits` 1.04 → 1.34.

Two things are stated about those numbers rather than left implicit. They are **real on that binary**.
And the **cumulative arm64 cost of the train was never judged as a distribution** — the per-change
verdicts were taken on x86-64 — so they are this stamp's reading, not an attribution to any one commit.

## Two defects found in the benchmark itself

- **§A published a fabricated number.** The engine path ran every competitor without a compile probe,
  so for `[a-z]++` — a possessive quantifier RE2 has no notion of — `re2_count` compiled nothing,
  matched nothing, returned 0, and the table published **"0.01 ns/B, 0.01× in REAL's favour"** with a
  count column reading `42108/—/42108/0`. That is worse than a crash: it looks like data and it
  flatters REAL by a factor of a hundred. All three competitors are now probed.
- **The same path aborted the whole harness on macOS**, uncaught, because libc++ throws on `[a-z]++`
  where libstdc++ accepts it.

## Compile time

`static_storage` measured its own program **seven separate times** — one `build()` per size, per
scalar, each its own top-level constant expression re-running the compiler front end. Collapsed to one:
**12 `build()` evaluations to 6**, and a five-`static_regex` translation unit compiles **6.9 % faster**
(4.47 s → 4.16 s median, slower on all three paired runs, ranges disjoint). The idea comes from an
`stx` staged-types incubation; the idea was taken and the library was not, so real-regex still has no
dependencies.

Two further ideas from the same source were measured and refused, with the numbers on the code they
would have replaced: a pack-expansion table builder (**identical** minimum `-fconstexpr-steps`, 177 734
for both forms — no wall-clock and no budget gain), and a named dispatch for the 67
constant-evaluation branches (35 of them are guards with no second branch to pass, and the nine
`(is_constant_evaluated() || !route_disabled())` sites need the short-circuit to keep a mutable runtime
seam out of constant evaluation).

## Verification

`exhaustive-compat` 3 218 434 cases, `agree` = 3 213 886, divergences = 4 548 (documented nullable-loop
capture, serious = 0) — **identical at every step of this train**, which is the control that decides for
changes to which route a broad pattern class takes. `fowler-compat` PASS. 859 tests, 346 560 checks, 0
failures, line coverage 96.55 %.

The local gate gained a step and now has 24: **`check-no-simd`**, because this train shipped a defect
that every other check passed. A filler copied `run_alternation`'s mask-carried block scan and not its
`#if defined(__ARM_NEON) || defined(__SSE2__)`; arm64 always defines the first and x86-64 the second,
so the gate, both benchmark legs and every layout campaign reported green while CI's 32-bit leg failed.
The new step is verified in both directions — green here, and the same three errors on the commit that
shipped the defect.

**§B (the Python binding table) is NOT re-measured for this train.** It carries a `2026.8.10` stamp,
which is what `make version-check` warns about, and the warning is accurate: this train's batching
changes exactly the `findall`/`sub` regime §B measures, so its numbers understate the binding. One
train stale rather than thirty, and left standing rather than quietly carried forward.
