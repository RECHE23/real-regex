# v2026.7.42 — the compat layer moves under `real/compat/`

**Breaking (opt-in surface):** the `std::regex` drop-in moved from `<real/std/regex.hpp>` to
`<real/compat/std/regex.hpp>` — the compatibility layer now lives under `real/compat/`, making
room for the upcoming RE2 drop-in (`real/compat/re2/`). Update the include; the namespace
(`real::compat`) is unchanged. No compatibility shim: the surface is young and has no known
adopters, so a clean move plus this note was preferred over carrying a deprecated forwarding
header.

Pure move, no logic touched: internal cross-includes among the four moved files (`regex.hpp`,
`regex_core.hpp`, `regex_iter.hpp`, `regex_match.hpp`) are relative and needed no change; every
external reference (README, docs, ~20 "Users:" comments across the engine headers, the test
suite, the fuzz targets, `setup.py`'s wheel-packaging comment, the doc-comment generator
template) was updated to the new path. Output is byte-identical — `tests/compat/` is unchanged
and stays green as-is; that was the correctness bar for this change.

The Go binding's vendored mirror (`bindings/go/vendor_include/`) was regenerated to match.

## RE2 drop-in, volet A: `\C`, the raw-byte escape

A design-first D0 spike (throwaway worktree, no commit) validated the RE2 drop-in's core design
against a real, locally-built RE2 (v11.0.0): `RE2::Arg`'s type-erased parser-cell mechanism,
`RE2::Set` mapping directly onto `real::regex_set::which()`, and leftmost-longest semantics
mapping directly onto the already-existing `real::regex::search_longest()`. The spike surfaced
exactly one real gap: RE2's `\C`, an escape that matches exactly one raw byte, unconditionally
(including a literal `\n`, unlike `.`), bypassing UTF-8 entirely — even under RE2's default
UTF-8 mode.

REAL now supports `\C`, restricted to `flags::bytes`. Outside bytes mode, a `\C` span can land
mid-codepoint; that's well-formed on the byte-offset C++ API (RE2 itself behaves identically
there), but it would corrupt any binding that converts byte offsets to character offsets (the
Python layer, for one). Rejecting `\C` outside bytes mode keeps every REAL-native surface
codepoint-clean by construction — the same call already made for `strict-dot` (see
`docs/divergences.dox`). Mechanically, `\C` reuses the existing byte-klass opcode (the plain
256-bit "any byte" class, unconditional — no dotall exclusion), so `\C+`/`\C*+`/`\C++` all
engage the existing class-loop fast path with zero new runtime wiring. Verified against the real,
locally-installed RE2 oracle with a dedicated differential harness: zero divergence.

This is volet A only. Volet B — the full `real/compat/re2/` surface (`RE2::FullMatch`,
`PartialMatch`, `Arg`, `Set`, `Consume`, `Replace`, `QuoteMeta`) — is separate follow-up work,
not part of this release.

## What's next

Volet B of the RE2 drop-in: the full `real/compat/re2/` surface, responding to
[issue #2](https://github.com/RECHE23/real-regex/issues/2). REAL is a strict syntax superset of
RE2 (compiles everything RE2 compiles, plus bounded lookarounds, possessive quantifiers, and
`\p{}`, which RE2 rejects outright), so the pitch is direct: migrate from RE2 without changing a
pattern, keep the ReDoS-safety, gain features RE2 refuses.
