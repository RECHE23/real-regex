# v2026.7.42 — the compat layer moves under `real/compat/`

**Breaking (opt-in surface):** the `std::regex` drop-in moved from `<real/std/regex.hpp>` to
`<real/compat/std/regex.hpp>` — the compatibility layer now lives under `real/compat/`, making
room for the upcoming RE2 drop-in (`real/compat/re2/`). Update the include; the namespace
(`real::compat`) is unchanged. No compatibility shim: the surface is young and has no known
adopters, so a clean move plus this note was preferred over carrying a deprecated forwarding
header.

Pure move, no logic touched: internal cross-includes among the four moved files (`regex.hpp`,
`regex_core.hpp`, `regex_iter.hpp`, `regex_match.hpp`) are relative and needed no change; every
external reference (README, docs, ~20 "Users:" comments across the engine headers, the test
suite, the fuzz targets, `setup.py`'s wheel-packaging comment, the doc-comment generator
template) was updated to the new path. Output is byte-identical — `tests/compat/` is unchanged
and stays green as-is; that was the correctness bar for this change.

The Go binding's vendored mirror (`bindings/go/vendor_include/`) was regenerated to match.

## What's next

This clears the way for `real/compat/re2/` — a drop-in for Google's RE2, responding to
[issue #2](https://github.com/RECHE23/real-regex/issues/2). REAL is a strict syntax superset of
RE2 (compiles everything RE2 compiles, plus bounded lookarounds, possessive quantifiers, and
`\p{}`, which RE2 rejects outright), so the pitch is direct: migrate from RE2 without changing a
pattern, keep the ReDoS-safety, gain features RE2 refuses. A design-first spike is queued next.
