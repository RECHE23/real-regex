## RE2 drop-in, volet A: `\C`, the raw-byte escape

A design-first D0 spike (throwaway worktree, no commit) validated the RE2 drop-in's core design
against a real, locally-built RE2 (v11.0.0): `RE2::Arg`'s type-erased parser-cell mechanism,
`RE2::Set` mapping directly onto `real::regex_set::which()`, and leftmost-longest semantics
mapping directly onto the already-existing `real::regex::search_longest()`. The spike surfaced
exactly one real gap: RE2's `\C`, an escape that matches exactly one raw byte, unconditionally
(including a literal `\n`, unlike `.`), bypassing UTF-8 entirely — even under RE2's default
UTF-8 mode.

REAL now supports `\C`, restricted to `flags::bytes` (a second gate, `flags::allow_raw_byte`,
widens this for byte-offset-native consumers — see the D1 section below). Outside either gate, a
`\C` span can land mid-codepoint; that's well-formed on the byte-offset C++ API (RE2 itself
behaves identically there), but it would corrupt any binding that converts byte offsets to
character offsets (the Python layer, for one). Rejecting `\C` there keeps every char-offset
REAL-native surface codepoint-clean by construction — the same call already made for
`strict-dot` (see `docs/divergences.dox`). Mechanically, `\C` reuses the existing byte-klass
opcode (the plain 256-bit "any byte" class, unconditional — no dotall exclusion), so
`\C+`/`\C*+`/`\C++` all engage the existing class-loop fast path with zero new runtime wiring.
Verified against the real, locally-installed RE2 oracle with a dedicated differential harness:
zero divergence.

## RE2 drop-in, volet B: `real/compat/re2/`

The full RE2-compatible surface, closing [issue #2](https://github.com/RECHE23/real-regex/issues/2):
`RE2::FullMatch`/`PartialMatch`/`Consume`/`FindAndConsume`/`Replace`/`GlobalReplace`/`QuoteMeta`,
`RE2::Arg`, `RE2::Options`, `RE2::Set`. Header-only, zero-dep — RE2 is never a runtime dependency
here, only the test-time oracle this layer was verified against; `real::regex`/`real::regex_set`
do all the work. Naming mirrors real RE2's own spelling exactly (`FullMatch`, `set_longest_match`,
`ANCHOR_START`, …), not REAL's own conventions, since matching what an RE2 user already types is
the entire point.

**No fallback, no exceptions.** `std::regex` compat can delegate an ineligible pattern to
`std::regex` (`policy::fallback`); RE2 is not a runtime dependency here, so there is nothing to
fall back to. A pattern or option this layer cannot honor is a clean, immediate rejection —
`ok() == false`, `error()` explains why — the same shape RE2 itself uses for a syntax error, so
callers already know how to handle it. This also matches RE2's own contract more closely than a
throwing one would: real RE2 has no exceptions at all (`RE2 re("(broken"); if (!re.ok()) …`).

**Scope.** Matches RE2's default mode (UTF-8, not `posix_syntax`). `posix_syntax`, Latin-1,
`never_nl`, and `never_capture` have no REAL-side equivalent and are rejected at construction
rather than silently ignored; `perl_classes`/`word_boundary`/`one_line` are inert here for the
same reason they're inert in real RE2 outside `posix_syntax` mode — its own documented behavior,
not a new divergence. `longest_match` is honored by every unanchored-search operation
(`PartialMatch`, `FindAndConsume`, `Replace`, `GlobalReplace`) via `real::regex::search_longest()`/
`find_iter_longest()` — REAL's own, pre-existing, documented RE2 `set_longest_match` equivalents;
the anchored operations (`FullMatch`, `Consume`) don't depend on it, since their overall match
boundaries are the same either way.

**A real implicit-conversion subtlety.** `RE2::FullMatch(text, "a.*b", &arg)` needs the string
literal to convert to a temporary `RE2` implicitly — but `const char[N] -> std::string_view ->
RE2` is *two* user-defined conversions, and C++ only ever applies one implicitly. A single
`RE2(std::string_view)` constructor compiles fine in isolation but silently breaks that exact
call pattern; caught immediately by a smoke test, not by inspection. Fixed the same way real RE2
itself is built: three separate non-explicit constructors (`const char*`, `const std::string&`,
`std::string_view`), each one hop from a literal/string/view respectively.

**Proof.** A dedicated differential harness against the real, locally-installed RE2 (v11.0.0, via
Homebrew + pkg-config — not a stand-in): 74 checks across `FullMatch`/`PartialMatch` with typed
extraction, `longest_match` boundary selection, `Replace`/`GlobalReplace` rewrite expansion,
`QuoteMeta` (byte-for-byte, including a NUL byte and UTF-8 continuation bytes), `Consume`/
`FindAndConsume` tokenizing loops, and `Set` membership — zero divergence. A tracked, REAL-only
unit suite (no RE2 dependency) exercises the wrapper's own contract, including every rejection
path and option; project-wide line coverage after this addition: 95.79% (floor 95.0%).

The Go binding's vendored mirror was regenerated to match (`real/compat/re2/` is new, so this
was a new-file sync, not a modified-file one — `check-vendor`'s diff check only catches drift on
already-tracked files, so this needed a manual `git status` check to catch).

## Hotfix: `\C` was silently reachable through `real::compat` (std::regex drop-in)

Caught by CI, not review: `real::compat` always compiles its internal engine with `flags::bytes`
(an implementation detail, for byte-per-`std::regex`-char alignment — see the `compat/std/regex.hpp`
file header), which happens to be `\C`'s only gate. So `\C` compiled and matched through the
`std::regex` drop-in even though it is not ECMAScript at all and `std::regex` itself rejects it — a
verdict divergence the differential fuzzer's `\C` corpus seed (added for volet A's own coverage,
replayed here since `fuzz/corpus` is shared across fuzz targets) found on its very first run.
Routed `\C` through `real::compat`'s existing `pattern_forces_std` pre-screen — the same mechanism
that already routes `\0`+digit and inline-flag groups to `std` for an analogous both-accept-
differently reason — so it is now rejected the same clean way on both backends. Verified: the
actual `fuzz_compat` harness, rebuilt with CI's exact sanitizer flags, ran 45s / 25,455 executions
over the full corpus (including the `\C` seeds) with zero crashes (previously crashed on load).

## RE2 drop-in, `\C` completed: text-mode parity, no more asterisk

Real RE2 accepts `\C` in its default UTF-8 mode; `real/compat/re2/` (volet B) rejected it, since
`options_to_flags()` never set `flags::bytes` — an oversight the original 74-check differential
never saw, because it only compared match results when *both* sides already compiled, never
accept/reject agreement itself. Closed with `flags::allow_raw_byte`, a second, independent gate
for `\C` alongside `flags::bytes`: accepted under either, for byte-offset-native consumers that
are not `flags::bytes` callers. Safe specifically for `real::compat::re2` because its whole API is
byte-offset C++ (mirroring RE2's own) — the char-offset hazard the gate exists to protect against
(e.g. the Python `str` binding, which cannot reach this flag) never applies here.

`real::flags` widens from `uint8_t` to `uint16_t` to make room (`bytes`..`dollar_endonly` already
claimed every bit of a `uint8_t`) — a zero-commit design spike confirmed this is layout-neutral:
`sizeof`/`offsetof` on `dynamic_storage` and every downstream struct, including `pattern_hints`
(the actual hot-matching-loop struct, which has no `flags` field at all), are byte-identical
before and after; the extra byte is absorbed by existing padding. The spike also confirmed, via a
route-instrumented differential (not inferred), that the existing `fixed_shape`, `class_loop`, and
`lazy_dfa_anchored` fast paths all already correctly handle `\C` mixed with codepoint-aware
opcodes in the same program — not just decline cleanly to the general VM, though `onepass` does
exactly that where it doesn't structurally apply, itself a safe, verified outcome.

Verified against the real, locally-installed RE2 (v11.0.0): 50 differential checks — accept/reject
agreement first, unconditionally, closing the harness blind spot that let the original gap
through — plus a byte-offset span cross-check via `Replace`, zero divergence. `full-local-gate`
18/18, project-wide line coverage 95.81% (floor 95.0%).

**The layout claim, measured, not just argued.** The `sizeof`/`offsetof` proof above is structural,
not a substitute for a runtime check on a change with this project's own history of layout
regressions (`small_set`, the work-budget carry). A two-ISA, interleaved-frozen-binaries A/B on
the `witness`/`fields`/`wplus` hot corpora (baseline `dcde510` vs this train) came back flat on
both: x86-64 within noise (~0.9% mean, below the noise floor, no consistent direction), arm64
min-of-11 at −1.67%/−0.31%/+0.43% (also noise — no consistent direction). No reorder needed.

Issue #2 closes clean: REAL's RE2 drop-in now compiles everything real RE2 compiles, `\C`
