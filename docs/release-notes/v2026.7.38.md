# v2026.7.38 — possessive captures, now correct

Correctness release, headlined by a fix to a capturing-group bug in the possessive
fast-path routes shipped since v2026.7.36; also ships two refactors from an internal
complexity/duplication self-audit (the "phase-R" train). No breaking API changes.

## Correctness — a captured possessive loop now captures its own last iteration

A captured possessive loop (`(a)*+;`, `([a-z])*+;`, `(\w)++`, …) returned the
**whole match span** — delimiter included — as group 1 on the fast path, instead
of the loop's own last successful iteration. `re`'s own semantics (and REAL's
general VM, which already got this right): `([a-z])*+;` on `"aaa;"` captures
group 1 as `"a"` at `[2,3)`, the last repetition — not `"aaa;"` at `[0,4)`. Shipped
live since v2026.7.36's original klass/klass_cp fast path; found by our own
recognizer work while extending the possessive-loop family (v2026.7.38 R2, below)
and disclosed, not silently patched around, in that commit.

Fixed by teaching the shared driver (`run_possessive_loop_generic`) the width of
the loop's own last atom — trivially 1 byte for a byte/byte-class body, a
backward UTF-8 decode (`codepoint_retreat`, mirroring the existing
`codepoint_advance`) for a code-point-class body — and capturing
`[body_end - width, body_end)` instead of the whole match. A zero-iteration
match (e.g. `(a)*+b` on `"b"`) now correctly leaves group 1 unset (`None`,
matching Python), not a bogus empty span.

The route-toggle differential harness that exists specifically to catch route-
auto vs forced-general disagreements had a proof gap: it only ever compared the
*overall* match span, never group spans, so this exact bug could — and did —
ship straight through it. Closed alongside the fix (`expect_route_toggle_agrees_group1`,
now used everywhere a captured possessive shape is exercised) — the proof gap
closes with the bug it let through.

## Refinement — typed class refs, byte-possessive captures armed, shape-envelope extraction

Three smaller changes from a complexity/duplication self-audit of the possessive
fast-path family (R0–R3):

- **Typed `class_ref{kind, index}`** replaces an untyped index-pair + bool-discriminator
  pattern used to identify which table (byte classes vs code-point classes) a
  possessive-loop recognizer's mandatory copy and loop body each refer to. A prior
  bug (v2026.7.37 #4) was exactly this: two different tables sharing a numeric
  index by coincidence, compared without checking which table either side came
  from. `class_ref`'s `operator==` compares kind first, making that whole bug
  class unrepresentable rather than a hand-checked invariant.
- **`a++`-style byte possessives get their own dedicated fast-path route**
  (`byte_loop_possessive`), closing an asymmetry the klass/klass_cp family already
  had: ×172 (dense corpus) / ×8.5 (sparse corpus) faster than the general VM,
  x86-64. The captured variant (`(a)*+;`) now arms too, on the back of this
  release's capture fix above — the gain is shape-dependent (which captured
  shapes arm at all is narrower than the bare/uncaptured family: only the
  star-with-mandatory-suffix "embedded capture" shape does, not bare `++`), but
  substantial where it applies (arm64: unarmed/general-VM speed → ~16× once armed).
- **A shared shape open/close envelope helper** in the fast-shape analyzer
  (`detect_fast_shapes`), extracted from 5 near-duplicate recognizer blocks.
  Net **+27 lines** — the LOC-reduction bar this refactor was measured against was
  not met, said plainly rather than glossed over; kept anyway for the shared,
  single-tested-once envelope-parsing frame it gives the 4 (of 5) recognizers
  it applies to (the 5th, `is_fixed_alternation`, parses backward and does not fit
  the same shape).

`capklass` (captured klass loop) shows a **+13.5% x86-64** cost relative to the
prior number on this route — this is the price of the capture fix above, not a
regression: the prior number timed a fast-path route that was returning the
*wrong* group span, so it was never a valid baseline to hold flat against.

## Verification

Full C++ test suite (590 tests, 52.7k checks); `make full-local-gate` 18/18;
line coverage floor holds (95.0%). The capture-fix's own oracle-verified matrix
— `{byte, klass, klass_cp} × {dense, sparse, zero-iteration, ascii/2-byte/4-byte
last atom}` against Python 3.14.6 — is reversion-proven: the identical test file
run against a `git worktree` pinned at the pre-fix commit fails 10 tests (39
checks); passes clean here. R3's shape-envelope extraction is proven byte-identical
(hints + compiled program, text dump) across an 18,056-pattern corpus; R2's
`class_ref` typing is proven via a decision-differential over the same corpus.
The differential fuzzer's 5-seed × 100,000-iteration closure criterion is clean
post-fix. A route-toggle A/B confirms the existing measured possessive routes
(bare byte/klass, quoted-delimited) are flat pre/post capture-fix on both ISAs;
see the capklass note above for the one route whose numbers legitimately moved.

## Honesty

The shape-envelope refactor (R3) did not meet its own LOC-reduction bar — reported
as a shortfall, not reframed as a win. The capture bug this release fixes was
found by our own tooling before it reached a user, and every bug this train
touches closes its own proof gap on the way out (the group-aware route-toggle
harness above; `class_ref`'s type-level fix for the index-collision bug class).
