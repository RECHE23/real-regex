# v2026.9.11 — four wrong answers fixed, and large alternations in bounded memory

**Four defects that returned wrong answers in released versions are fixed**: a loop over an alternation
with an empty branch ran past an empty iteration on subjects over 512 bytes; a regex assigned one
alternation over another could search with the previous one's filter; a text-mode pattern that opens on a
raw UTF-8 continuation byte (`\xA9`) matched inside code points; and the lazy DFA's scan for a pattern with
assertions could, in rare cache states, report a truncated match end. **Large alternations now run in
bounded memory**: the Aho-Corasick automaton is built over the pattern's byte classes under a 32 MiB budget
(14 500 words: 276 MB → 25 MB, and 1.8–2.8× faster), and a lazy DFA's cache flushes past 64 MiB per
direction (the same words followed by a digit: 258 MB → 78 MB). Alternations with more than eight first
bytes, case-folded alternations and alternations opening on a class now scan by a fingerprint. The
`std::regex` drop-in replaces and iterates nullable patterns itself, as the standard specifies, and the RE2
drop-in honours `max_mem`.

## Fixes

- **An assignment clears the alternation plan** (eee17e3). A `regex` assigned an alternation whose
  compiled program was the same size as the one it held reused the program's buffer, and kept the previous
  pattern's byte-pair or fingerprint filter: on a dense subject, 2 matches of 2 500. Present since
  v2026.9.10 (Go `v0.3.9`).
- **In text mode no match starts on a UTF-8 continuation byte** (9265787). A pattern whose first byte can
  be `0x80`–`0xBF` — a raw `\xA9`, `\xA9|zz`, `\xA9+`, `(?a)\b\xA9*z` — was found inside code points by the
  literal, alternation, loop and fixed-shape routes and by the lazy DFA, and so by a `regex_set`'s members:
  `\xA9` matched the tail of `é`. Such a pattern is now answered by the VM, which holds the rule; no other
  pattern changes route (`.`, `\W`, `[^a]` and non-ASCII literals do not). Under `flags::allow_raw_byte`
  (the RE2 drop-in) a `\C` lead still starts inside a code point, as RE2's does.
- **The lazy DFA's scan with assertions quits when a cut flushes its cache** (3cda131). The flush that
  trips the thrash detector could land in the cut after an accept, which handed back the dead state; the
  scan then reported the match end reached so far instead of quitting to the VM. Not reproduced at the
  default cache size; with small caches, 64 wrong answers in 10 240 (`(?m)[a-z]$[^ ]+\B`: 7 for 9).
- **A loop ends on an empty iteration in the lazy DFA, as in the VM** (606430e). Where an empty
  iteration reaches a loop's head again at one position, the loop exits there before any branch that would
  consume; the lazy DFA, which answers most searches past 512 bytes, kept looping. `(?:c||b)+` over `ccb`
  matched `ccb` where Python's `re` and REAL's own VM match `cc`; on random loops over alternations with an
  empty branch, 653 of 3 000 patterns answered differently from the VM, none now.
- **RE2 drop-in**: `FullMatch("+12", &i)` parses a leading `+` as RE2 does (15582ad); `Options::max_mem`
  bounds the compiled program at two thirds of it, with `ErrorPatternTooLarge` and RE2's message, and a
  program past REAL's own limit now reports that code rather than `ErrorSyntax` (bcb635b).
- **`std::regex` drop-in**: an error the `std` backend raises while matching is `compat::regex_error`, as
  documented (d2e28f6); the lazily built `std` engine is read without a lock (15582ad).
- A null `const char*` subject reads as the empty string on every overload.

## Behaviour

- **The `std::regex` drop-in replaces and iterates nullable ECMAScript patterns on REAL** (77cce0e),
  advancing past an empty match as [re.regiter.incr] requires, including the retry without context after
  the first empty match. libstdc++ agrees on all 160 650 cases of the differential. Apple's libc++ drops
  the text between two empty matches and LLVM's retries with context; both are detected, and REAL follows
  the standard on every platform. A 100 KB field that crashed libstdc++'s `std` route now runs, and a
  1 MiB `[^,]*` replace takes 19.6 ms (libc++ 127.8, libstdc++ 36.4).

## Performance

- **The Aho-Corasick automaton is built over byte classes, in one byte budget** (f909587). The trie is
  built sparse, then laid out as a dense table at its exact size; past 32 MiB the sparse trie is searched
  with dense rows for its shallowest nodes, and past what the trie itself may take the pattern takes the
  ordinary alternation route. A case-folded branch is one path, not one per spelling (4 000 six-letter
  words with ASCII case folding: 546 MB → 2.2 MB). 14 500 random words over 256 KB: 3.38 → 1.20 ms on arm64;
  6.10 → 2.43 ms on x86-64 at `-O2`, `-O3` −63 %. An assignment releases the automaton.
- **A lazy DFA's cache flushes on its bytes as well as its states** (55257dd): 64 MiB per direction,
  above any working set measured without a quit (30 MB for 2 000 words). `(?:14 500 words)[0-9]`: peak
  258 → 78 MB. Nothing measured below that size changes.
- **An alternation with more than eight first bytes scans by the fingerprint** (033856b) instead of the
  automaton's byte walk: 12 literals absent from 500 KB of log lines, x86-64 −96 % cycles, arm64 1.40 →
  0.05 ms. Alternations opening on a class (a6a8541) and case-folded ones whose folds leave ASCII (093833d)
  take it too: `(?i)info|error|warn` ×0.15 in cycles on x86-64.
- **The fingerprint's tables are loaded once per scan** (ebe27d1): GCC at `-O2` reloaded them every block —
  the build the Go module and CMake's RelWithDebInfo use. Ten words −17 % (AVX2), info|error|warn −30 %.
- **The Aho-Corasick gate's sample stops walking branches past a budget** (4166e27): a 1 000-word
  alternation on 100-byte lines, 1.59 M → 45 k instructions per search.
- The lazy DFA's state ids are their rows' offsets (c6b9556); an inner-literal candidate leases its DFAs
  once rather than twice (4fec155, IPv4 −9 % cycles on x86-64, −14 % on arm64); fixed-shape walks fill their spans in
  batches (cadffe8, date 1.12 → 0.92 ns/B on x86-64); the AVX2 literal scan tests four blocks at once
  (58b9705, `hello` −33 %); the fixed code-point shape reads an ASCII atom off the class bitmap (600b0fb).
